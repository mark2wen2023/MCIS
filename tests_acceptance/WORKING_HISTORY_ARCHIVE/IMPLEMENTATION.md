# Supplemental extraction-working history archive

Service `agents/working_history_archive.py`, explicit initialize/grant, no HTTP route. Payload format extraction-working-supplement-v1 carries canonical SHA256 integrity checksum, case/origin generation/export epoch, and up to50 immutable proposal results with complete review history. No operation IDs/operation digests/providerKey/session/permissions. Citations/spans and original unverified model receipt retained. Coverage explicitly excludes full original interviews, evidence bytes, identities and grants; this is not `.mcase`, complete backup, original-source restoration or live working-history replay.

Export requires current live read authorization and exact complete record/policy/original-source binding. It cannot bypass live historical access restrictions. All rows materialized within one SQLite transaction and all source/auth/epoch checks repeated before returning. Export fails rather than silently omitting inaccessible/oversized history.

Import/read use dedicated ArchiveGrant(subject,targetIncarnation,can_import,can_read), separately opt-in and default-denied. can_import never implies can_read or live WorkingGrant. Both also require current case fullcontent and testimony policy. Same caseId may import an old/different origin incarnation; target current incarnation/epoch recorded and checked on subsequent reads/replay. Origins, authors, sources and inference metadata are unverified historical claims. Only ImportedWorkingArchive is written; no live Proposal/Review/Subject/Grant/source/interview activation. SQL UPDATE/DELETE triggers reject normal modification. The deliberate read boundary differs from live history: dedicated archive-read authorization permits explicit untrusted history even when old original bindings no longer exist. This does not attest old evidence.

Strict JSON rejects duplicate keys, nonfinite values, unknown fields, wrong case IDs, malformed hashes/UUIDs/timestamps, repeated proposals, bad record/citation association, wrong span lengths, non-Draft statements, inconsistent fixture/local declarations, discontinuous review revisions and incomplete/duplicate decisions. Limits8MiB total,50 proposals,100 reviews each,20 proposals/decisions per result,1000-character review note,20 imported bundles per target incarnation. SHA is not a signature; changing author claims and recomputing checksum never creates an identity.

## Schema/authentication review updates

Added explicit sourceDeclaration per proposal: null for interview_document_only, otherwise exactly evidenceId/sourceIncarnation/sourceSha256 with strict nonempty ID, canonical UUID and lowercase SHA256. Export resolves the declaration through source_current within the same bound transaction and repeats binding checks afterward. The declaration remains an untrusted historical claim on import; no originals or active source index are restored.
