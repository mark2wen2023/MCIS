# W12 同案换版：可执行验收条件

本轮只固定条件，不执行、不改产品。通过必须以真实本机 API（仅 127.0.0.1）及（若验 UI）正常沙箱 Chrome 的原始响应为准；HTTP-only 或 DOM 模拟不得冒充浏览器结果。不把跨案、等候帧或窄屏布局的通过当作本项通过。不是 W12 整包。

## 材料

一案、同一批已登记船舶、两套纯合成航迹输入，身份分别为 digest A 与 digest B（`previewDigest` 及对应 `sourceSha256` 均不相同）。禁止使用真实案。

## 条件

1. **先标旧结果失效。** 当前身份从 A 变为 B，或 A 被撤回、尚未得到 B 的结果时：分析读取与页面不得再展示 A 的指标、曲线或 A 的身份；须进入「无当前分析 / 正在读取」一类状态。仅切案号或操作者身份的既有失效不够，同案换版也必须失效。
2. **再用确切新输入。** 仅当 B 的登记回执与当前点按现有完整性规则核对通过后，才允许出现 B 的分析结果；响应必须携带 B 的登记身份（`caseId` / `vesselId` / `previewDigest` / `sourceSha256`），并与 `GET /track-imports` 对同一输入的只读原件一致。不得用种子文件哈希冒充该身份。
3. **无源即无结果。** 本案计算所需船舶没有已验证的当前本地回执或当前点与回执不一致时，分析不得返回可用结果，也不得用种子、归档历史或他案数据填补。
4. **旧响应不可回填。** 身份已切换到 B（或已进入无源）之后，迟到的 A 列表/详情响应不得写回界面或当前快照。显式重新读取只接受与当时身份一致的响应。
5. **换版动作前提。** 若产品仍无经授权的同船换版/替换写入，则「一案两版本」持久化未接通，本套条件不得报通过；应继续报告该断点，而不是用两艘船或两案冒充同案换版。
