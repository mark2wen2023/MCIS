# Pi working history and review-origin archive v2

New exports use extraction-working-supplement-v2. The reader still accepts v1
with its legacy fixture/local shapes; v1 cannot claim Pi or new reviewOrigin
fields. V2 preserves strict Pi provider/model/completion mode, exact proposal
quotes/spans/citations and bounded host protocol trace. Export rechecks current
source bytes/policy/session and the stored output digest; no mutable metadata
is allowed to confer permission or factual authority.

The supplemental package still excludes originals, credentials, permissions and
active identities. Restore only adds immutable untrusted history in the target
case incarnation/epoch, with separate import/read grants and final authority
checks. It does not create live proposals/reviews, fact assertions, sessions or
new model runs. Its outer checksum checks transport integrity, NOT authenticity.
The Pi outputDigest in imported history is a claim/format-checked hash, not a
proof: recomputing it needs the original source digest, which is intentionally
not reconstructed from quoted fragments. A changed historical claim with a
recomputed package checksum remains untrusted; UI must not label it verified.

New review records carry server-origin metadata:
- user_submission_unverified: submitted through an authorized user-facing host,
  not proof that a biological human authored it or that the opinion is correct;
- scripted_test: an explicit trusted acceptance-script exercise;
- missing legacy origin: unknown, never relabeled human or inferred from note text.
RPC clients cannot choose this origin. Existing same-operation legacy review
retries preserve their old missing-origin record rather than silently upgrading
its provenance. Scripted and user-origin operations cannot impersonate one another.

Existing Pi proposal read/list/per-item review RPC remains scope-bound. This
slice does not enable remote generation from UI or add a network endpoint.
Runtime identity/trace authenticity remains unverified; no deployment/CI claim.
