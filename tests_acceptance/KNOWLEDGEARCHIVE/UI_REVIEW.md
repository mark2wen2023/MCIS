# 知识归档 UI 开发中独立检查

不是整体验收，后端尚未冻结。本检查未改 UI/业务实现。

`browser_identity.py` 使用真实 Chromium 和 Vite，但服务端响应为明确 API doubles。4 个独立场景通过：挂起预览、历史详情、原包导出、保存响应，在实际顶栏切换身份后释放原请求。旧摘要/正文不显示、旧下载不触发、迟到保存不误报成功；已发送保存仅保留摘要未知标记，切回后仍禁止新保存。页面错误列表为空。

静态检查：页面 context 改变会重挂载；下载在分块读取和摘要计算后再次验证身份/context，只有字节 SHA 一致才下载；保存未知状态保留跨 reload 的摘要标记，不保存正文。403 清空面板正文、列表、预览。

已知可用性边界：所有保存错误（包括明确的 4xx）都保留未知锁，只有同摘要 GET 成功才能解除。若服务明确拒绝并一直 GET404，该页面不能继续新保存。这是保守策略，不是保存成功，也没有自动重试或用户强制解锁。未来若增加已知拒绝白名单，必须按后端能够保证事务未提交的具体错误码设计，不可对所有 status<500 一概清锁。坏201、提交后503、404均不足以宣布未提交。

待正式冻结后仍需真实服务验收：保存成功丢响应→同摘要恢复、全角色接口权限、原始字节/元数据完整性、同包并发与故障回滚、在线状态不激活、在线库超归档预算后仍可撤回、增量预算拒绝。API doubles不证明这些后端行为。
