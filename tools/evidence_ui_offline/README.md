## 使用

自行准备两个独立检出及已有离线 Node/工作台依赖：工作台检出固定 `16eab9998ca9efe81b32ae9f82cf36511f0a3f01`；媒体检出包含本次新入口的交付提交（其固定产品基线为 `dc5023261a4ef8c344e2e6bd0c32587fa1e60219`）。不要把媒体检出切回 dc502326 后调用其中的旧入口：那时入口仍冻结旧产品。新入口允许包含基线且受测文件摘要完全一致的后续交付提交。然后在这份媒体检出中运行（替换为自己的目录）：

```sh
python3 tools/evidence_ui_offline/run.py \
  --workbench /path/to/workbench-checkout \
  --media /path/to/media-checkout
```

目录必须是两个不同且互不嵌套的 Git 检出根。可为完整或 sparse 检出，但 `inputs.json` 明列文件须存在；浅克隆须已有基线对象及可证祖先链。脚本不 fetch、不换分支、不安装、不启动服务，不复制或查看业务数据。不要加入或打开真实资料；clone 本身不证明数据净化。

先核对基线祖先、逐个源码/测试 SHA-256 及直接使用的离线依赖版本，再运行固定测试。后续提交不会被覆盖：若只追加不相关记录、明列文件不变可继续，打印真实 HEAD；若受测文件变更则失败，须另行审查更新清单，不自动放行。清单和脚本需来自可信本候选；这不是防恶意环境的沙箱或全依赖供应链证明。依赖版本核对不等于 wheel/npm 内容校验；使用受控、无并发修改的检出与既有依赖环境。

要求 Python 3.9+（标准库 Path.is_relative_to）与支持 node:test 的 Node，推荐复用本次核验版本；实跑 Python 3.12.14、Node v24.22.1，复用 esbuild0.28.2、React/ReactDOM19.3.1、react-router(-dom)7.18.5、scheduler0.28.0；未安装新依赖。缺文件/基线/依赖、版本不符、子进程错误、超时或缺完成标记退出非0，不能计通过。只有最终打印 `PASS OFFLINE REPRESENTATIVE CHECKS ONLY` 且退出0才完成本范围。不会改产品源码；临时完整/限定 HTML 自动清理。

3. 入口自身：`python3 tools/evidence_ui_offline/test_runner.py`，4项标准库自造目录/子进程替身检查（源码缺失/变化、同目录误用、缺依赖、失败/无完成标记）。

## 必须区分的交付边界

- **独立页仅编辑目标号**：已加载 A 的来源/行/草稿可以继续保留，但须明确标示新目标 B 未载入、旧内容属于 A。这是现有上下文测试所验，不表示已经切到 B workspace。
- **真正工作台切案尚未接线、未验**：有草稿时取消切案保留 A；确认切 B 后，即使 B 等待/失败、A 的成功响应迟到，B workspace 也不能显示 A 元数据、行或媒体。须在授权的隔离全链路中验收，不能拿独立页保留旧内容的测试代替。
- 同案登记回执→已有图音结果导入：此处只验字段映射、合成失败不接纳 UI 等；不证明登记成功、后端没创建或授权交集。
- 保存冲突：替身精确412业务码保留草稿；未知仍未知。真实并发提交/审计不在本轮。
- 刷新重开：合成地址和响应回放验证当前运行，不是实际浏览器刷新或固定报告历史。
- 后续需要同源装配、可信身份与权限交集、已批准隔离环境，实际走同案导入→核对保存→冲突处理→重开；报告冻结持久关联与授权导出重开另待接线。当前不启动后端/归档，不提供假工作台链接，不合并或部署。
