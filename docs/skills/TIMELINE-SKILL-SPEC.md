# SK-T01 多源时间线核查 Skill：实施规格 v0.1

状态：设计草稿，待业务专家审阅；不是已加载的 Skill、不是生产能力、不是已通过的模型评测。
来源：用户 2026-11-13 对渐进调查、时间线辅助、Skills、内网数据和海青君的要求；用户上传《智能体 Skill 调优“焚诀”——业务逻辑之外的胜负手》的分层、路由、代码护栏和反例回归经验。本文海事适配是设计建议，不是该文章的原话或法律规则。

- [PR46](https://github.com/mark2wen2023/MCIS/pull/46) `31c2a896d1717a7876a416f7d8ca295fa41378b8` 为独立研究模型，非生产路由；缺权限、摘要校验、严格全字段解析、时区适配、漂移仲裁和集成。其确认布尔值不能视为可信授权，字符串时间基准不能证明真实 epoch。
- 案件参数和 CSV 导入不等于内网 AIS 连接器。本文不宣称接通 OCR/ASR/视频、真实模型或内网系统。

## 2. 技能职责与路由

输入问题例如“核对 CCTV、AIS 和笔录的时间是否一致”“这两条记录谁先谁后”。输出是有来源的比较候选、缺口和核实建议，不认定事件身份、因果、避碰义务或责任。

适用：同案件至少两条可见记录，需要时间顺序、区间重叠或明确直接先后约束核查。
不适用：单纯船舶身份查询、自动事故定责、纯空间轨迹推演、无授权案件材料。身份不清先转身份核查；材料时间未解析先返回缺口，不编造时刻。若请求混合任务，先展示拆分计划，不静默扩大查询窗口。

技能描述先加载：适用/不适用、所需输入、允许工具、输出契约。公共规则只加载一次；专门时钟校准方法按需载入。文档内的命令、提示词和证据文本均作为不可信内容，不可改变系统权限或工具白名单。

## 3. 输入与可信边界

以下是待实现的逻辑契约，不是现有 API 名称：

- 可信服务上下文：operator_id、case_id、任务会话 ID、角色权限、允许查询范围、skill_version、model_version、工具策略版本。由服务端生成，禁止相信 LLM 或浏览器提交的权限布尔值。
- 来源引用：evidence_id、immutable_revision、digest、locator（页/段/音视频时间码/轨迹点范围）、original_time_text、来源分类 Public/Synthetic/其他授权材料。来源分类由可信证据登记提供，不由模型自行声明。
- 时间表达：绝对点或区间（明确时区/UTC 偏移）、相对顺序（A before B）、未知。区间表达使用闭区间，本版只判严格先后；接触边界或重叠一律不证明同一事件。
- 校准记录：clock_id、revision、作用于哪些记录与原始时间范围、目标时间基准、signed_offset、uncertainty、依据引用、审核状态、审核者。校准适用范围、权限和审核状态由服务验证。适用窗口必须覆盖原记录的整个不确定区间；跨窗口边界的记录本版不得整体套用校准，返回 unresolved。
- 初始查询窗口和规范化窗口一同保存；未知日期、时区或 DST 二义性不得默认用服务器本地时区。所有数值必须有限、单位明确、精度受限；超限失败而非静默四舍五入。

相同名称不证明相同船舶，相同时间不证明相同事件。工具每次读取都重查案件权限和版本；权限撤回后禁止继续提供原文或下发迟到结果。缓存至少绑定案件、操作者授权版本、证据版本、技能版本和查询条件。

## 4. 有界执行流程

1. 解析用户意图，明确比较目标和范围；拒绝无权限材料。无法判明目标时要求澄清。
2. 服务端读取已授权来源快照；原始文本不可覆盖，LLM 仅提出时间候选并保留原文定位。
3. 程序校验来源引用、时间格式、时区、区间顺序和校准范围。缺项进入 unresolved。
4. 程序进行规范化与确定性比较。LLM 不自行算时差，不自动估计钟差，不把校准候选当已批准校准。
5. LLM 可以解释程序结果、提出待核实问题；每个陈述指向结果 ID 与原始证据，不新增未在结果中的“事实”。
6. 输出预览。调查员逐项确认、驳回或保留；必须记录理由及依据。任何新证据或版本变化都会使旧预览过期，需要重跑。
7. 保存只允许通过人工操作与当前权限检查；当前切片不实现保存、报告采纳、问题卡写入或归档。未来写入必须幂等并有事务/审计。

建议原型默认预算：最多 50 条记录、100 个显式选定比较对、8 次只读工具调用、2 次模型解释尝试；服务端可配置，耗尽返回已完成部分及未处理列表，不声称全量完成。具体时间/Token预算须用部署模型实测后设定。停止等待不承诺上游已停止，但取消后不接收迟到结果、不自动写入。

## 5. 确定性比较契约

本版只支持已审核且范围匹配的常量钟差。定义 `target = original + offset`，offset 符号必须显式；clock uncertainty 与原记录不确定性按保守区间合成，不叫概率置信度。

例如原始闭区间 [100,102] 秒、offset=+5 秒、校准误差±2秒，扩展后为 [103,109]。B=[110,112] 则 A strictly_before B；B=[109,111] 则仅区间接触/重叠，relation=overlap_or_touch；严格先后及事件身份仍无法判定，而非“同时”。数值示例为合成测试，不是实际事故。

- 若 max(A) < min(B)：strictly_before；反向为 strictly_after。
- 其余：overlap_or_touch，不能据此认定同一事件。
- 基准不同、校准未批准、时区未知、纯相对时间与绝对时间混比：unresolved。
- 多个重叠校准、漂移、分段时钟跳变：本版 unsupported，禁止自动挑最有利的一个。
- 直接约束 A before B 与数值区间的冲突是候选。传递矛盾/图环检测是独立能力，若未实现必须返回 not_checked，不能报告“没有矛盾”。

## 6. 受控工具与输出

拟议工具仅三类：读取案件可见时间记录、执行纯比较、读取已授权原文片段。不提供通用 shell、SQL、任意 URL、全局连接凭据或发布工具。由 MCIS 网关包装，Pi 只调已批准入口。

结果包包含：run_id、上述版本快照、status（needs_input / partial / completed_preview / cancelled / failed）、逐记录规范化及其依据、逐对 relation 和比较基准、unsupported 项、未处理项、核实建议、审计引用。completed_preview 仅表示本次范围内流程结束，不表示事实已证实。

每个结论区分 observed（原文陈述）、computed（程序结果）、hypothesis（LLM 待核实解释）。每项包含证据及版本、定位、校准依据、人工 review_state。输出 JSON 必须验证白名单字段、引用存在和权限；未知字段拒绝。来源复述不等于来源真实性已验证。

## 7. UI 与人机边界

案件时间线页右侧海青君调用此 Skill；顶部固定显示案件、查询范围、版本及“分析建议，待核实”。中央并列原始时间和校正时间，展开显示误差区间与校准依据。每个冲突卡可跳原文，可“待核实/已核实/驳回”，但这些按钮仅在后续持久化契约验收后启用。没有生产服务时只展示明确的模拟预览，不做假保存。

## 8. 交付顺序与验收门槛

A. 当前：专业规格＋反例清单，独立文档审查；业务专家尚需审核。
B. 下一步：对接 W2 的只读工具适配，固定版本来源与授权测试；不能用 #46 研究布尔权限替代生产授权。
C. 真实模型受控调用：先用明确合成/公开授权材料，固定工具结果，评测路由、引用忠实性、缺口与解释；失败停止或待澄清。
D. UI/服务/数据库闭环：真实浏览器、权限撤回、重试、取消、重启、审计、版本过期；之后才接报告/问题卡/归档。

必须分别报告：路由评测、确定性代码测试、模型质量评测、真实端到端验收。独立 holdout 不写入技能示例；模型/技能/工具策略升级需重新回归。不得用模型自评分替代调查专家裁定，也不以测试数量直接给项目完成百分比。
