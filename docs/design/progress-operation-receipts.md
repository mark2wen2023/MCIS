## 建议合同（待审定，不是现有接口）

服务端先签发不可复用的 operationId，并持久绑定：案件、建议、可信主体、
动作类型、expectedRevision、规范化请求摘要及规范化版本。提交载荷含百分比和完整说明；
摘要是关联校验，不是授权凭据。操作ID不可跨主体/案件/建议转用。
签发失败或响应丢失时不得派发写入；签发本身不改变建议。

操作行至少包含：上述绑定、状态、签发/终结时间、结果revision、审计seq、
结果码和结果摘要；必要的完整说明存入受同等访问控制的操作载荷/结果记录，
不依赖截断的审计摘要。保存精确执行结果，而非仅保存可变当前记录的链接。
回执不得包含令牌、原件或无关案件资料。保留/删除周期须与审计及归档合同一起审定。

只读核对返回操作结果与当前建议版本，两者明确分开：

| 持久观察 | 可显示结论 |
| --- | --- |
| committed | 此操作已提交；展示提交版本和对应审计，不称当前值仍相同 |
| no_change | 此操作已终结且没有业务变更；说明没有新增进度审计/保存独立说明 |
| conflict / rejected（已持久终结） | 此操作未改变建议；不得自动以新版本重发 |
| issued / 查询超时或失败 / 缺失 / 不一致 | 未确认最终结果；保持阻断 |
| cancelled（若以后实现） | 仅在事务性终结已证明执行不可能再获准时可称未执行 |

缺少记录或“尚未执行”观察不证明不会有迟到提交；issued 也可能已有请求在途中。
不提供基于等待时间自动判定失败的逻辑。取消及后台恢复不在首个实现范围。

## 事务边界与版本比较

1. 签发事务只创建绑定操作行；客户端须取得可核对的持久ID后才允许显式提交。
2. 执行事务重新检查现有业务权限和主体绑定，锁定/原子领取该操作，核对请求摘要。
   同ID同载荷终结后只能读取既有结果，不重新执行；不同载荷拒绝，不覆盖原回执。
3. 在同一事务内检查 expectedRevision、业务状态及数值，更新建议、递增revision、
   追加审计并终结回执。全部提交或全部回滚，不允许先回成功回执再提交业务。
   实际数据库的锁/条件更新语义必须另行验证，Python线程锁不证明跨进程互斥。
4. 版本不符时不更新建议；如允许写冲突回执，该回执须与“未修改建议”在同一事务终结。
   权限拒绝的错误不应泄露操作是否存在，也不必承诺产生可查询回执。
5. 提交返回不明时保留原ID，只执行授权的只读核对，不重发或删除。
   事务回滚后 issued 可保持未终结；不能仅凭它解锁。首版不承诺自动恢复执行。

所有影响建议状态/内容/进度的写入口必须共用服务端revision规则；仅给进度入口
加版本无法防住其他写入口覆盖。比较用持久单调版本，不用时间戳或百分比，防止ABA。
旧数据只建立迁移后的版本基点，不补造旧操作回执或历史版本。
旧客户端不能静默绕开新比较；需明确的新协议及迁移/停用安排，未审定前不接生产。

## 同百分比语义

保留既有业务语义：在版本检查通过后，同百分比且无其他修改为 no_change；
不把说明偷偷当成独立日志保存，也不声称新增了进度审计。
操作回执可保存“请求了什么、未产生变化”的信息，并明确它不是已采纳的业务说明。
若希望支持独立说明，应另立业务动作与审计合同，不借本次修复扩展。
即使当前百分比相同，expectedRevision 已过期也先冲突，不能以相同值绕过版本核对。

## 权限、跨会话与界面

读取回执仍重新检查现有建议内容/审计权限；知道operationId不授予权限。
现有角色/操作者请求头属于自报身份，不能满足可信主体绑定，是正式接线前置阻碍。
不得新增高权限头或降低检查。多用户可读范围及是否可核对他人的操作需明确批准，
不能从现有写权限自动推导。

界面保留提交快照与后续草稿，核对不覆盖输入、不自动解锁发送。
终结回执只结束该操作的不确定性；下一次修改仍要读取当前版本并由用户明确决定。
跨会话需经授权的“我的操作”恢复途径，不能仅靠当前内存ID；不默认将完整草稿或
敏感载荷写入浏览器持久存储。旧会话未获得操作ID的请求仍无法追认，只能保持未知。
操作回执不是取消证明，也不保证另一用户随后没有修改。

## 上线前必须验证（清单不构成执行授权）

- 普通提交：建议、版本、完整操作结果与审计关联一致；响应丢失后可只读核对终结结果。
- 同ID重复与并发、不同载荷、跨进程领取：至多一次变更，无覆盖回执或重复审计。
- 两用户同版本及ABA：一个成功后另一个冲突；所有相关写入口均参与版本比较。
- 同百分比无变更、不同说明、过期版本：no_change与业务审计语义明确。
- 提交前后故障窗口、事务结果未知、重启：无虚假成功、盲重试或删除。
- issued、缺失、查询失败、历史无回执：保持未知，不用时间或相似事件推断。
- 权限收紧、主体可信绑定、跨案隔离及回执隐私：另行获得安全验证授权后执行，
  绝不借本清单重试已暂停的安全/拒写测试。
- 旧数据库/客户端、审计截断与分页、归档恢复兼容：历史回执不可重新授权执行；
  不支持的新表/状态继续遵循整包拒绝保护，不简单扩大白名单。
- UI保留输入、切案/切身份/跨会话、迟到核对响应及正常浏览器验收。
