## 演示顺序

1. 用独立空数据库 A 启动本地服务，确认大厅无案。记录实际版本及当前演示身份。
2. 大厅新建明确标注“合成”的案件。船参、证据、CSV、笔录均使用 runner 提供的合成样本；每次明确确认后重读实际保存状态。
3. 报告页选择真实案件，生成草稿，展示来源/接线限制；人工复核只演示流程，不宣称确认事故事实。
4. 导出受限 .mcase，记录 SHA 和字节数。不能只看 verify 通过就宣布可恢复。
5. 独立空数据库 B：上传同包、阅读范围/警示、明确确认。重开案件、笔录、报告；观察恢复历史说明并核对原件下载。不得在 A 上删除同 ID 以制造“恢复成功”。
6. 知识库单独演示候选→明确审核→发布/撤回；检查新快照保存，旧历史缺口仍标未知。
7. 导出独立知识 JSON，在另一空库保存只读历史。展示在线知识库没有因此增加卡片；历史 Published 仍只是历史。
8. 以真实响应/下载摘要和本次浏览器日志作为证据。失败当场记录，不用模拟成功或截图替代。

## 浏览器执行

runner 用 `--hold` 完成后，在另一个终端执行：

```bash
MCIS_BROWSER_BIN=/path/to/chrome-headless-shell python tools/stage-demo/browser_check.py /path/to/run.json --output /new/browser-output
```

需要带 Playwright 的 Python。脚本为每个真实服务启动本机 Vite，绝不拦截 API，不直接写数据库；浏览器检查重开页面、恢复标记及知识历史原包下载，不冒称全部表单已由 UI 点击录入。`browser-result.json` 单独记录结果，失败保留已完成步骤。脚本只结束自身启动的 Vite，不结束 runner 后端。

## 重跑与本机进程安全（准备检查，非端到端通过）

浏览器工具在任何 HTTP 前拒绝非 `passed/running` manifest；逐个核对 Linux `/proc` 中 PID 的命令行、此运行专属数据目录和 127.0.0.1 监听 socket 所有权，运行中在每次页面切换及下载前复核。过期 manifest、进程消失或端口转属其他程序即拒绝，不尝试连接其他已有服务。该检查依赖 Linux `/proc`，不支持的平台直接失败。新输出目录必须不存在，不能覆盖此前证据。

Vite 与 Chrome 子进程仅继承 PATH/HOME/TMPDIR/语言设置，移除外部 HTTP 代理、NODE_OPTIONS、模型/API 环境配置。urllib 显式禁代理；Chrome 显式禁代理和背景联网，DNS仅允许本机解析；本脚本不会点击来源网站链接。只结束本脚本创建且仍在运行的 Vite 进程组，不向 manifest 后端 PID 发信号。后端由 runner 管理。生产认证、系统级网络隔离以及进程对抗防护不在此演示范围。

## 本次实际自测结果与复跑方法

2026-11-12，本轮 `main 4a631205` + 本演示工具：真实 HTTP runner 全流程成功；真实 Chromium 浏览/下载 15 项检查通过。无 API mock、无 ORM 造数、无 LLM 调用、未部署。最终证据目录：

- `/tmp/mcis-stage-demo-browser-owned4/run.json`：API 全流程 `passed`，退出后 `running:false`。
- `/tmp/mcis-stage-demo-browser-owned4-results/browser-result.json`：浏览器 `passed`；截图与下载原件同目录。

这些是本机临时自测路径，不是交付服务地址。复跑将产生新的随机端口、ID 和摘要，应使用该次 manifest，不复用这里的 PID。

实际浏览器覆盖：源案与恢复案大厅、船参、航迹点位、证据清单、笔录重开、已存报告版本；恢复案笔录/报告历史提示；源库本地 W10 回执仍可读；恢复案旧回执被拒绝而独立历史可读、CSV 下载与原合成字节完全相等；知识历史浏览及原包 SHA 校验下载。历史下载会产生当前访问审计，因此“只读浏览”不代表数据库零写入；没有通过浏览器修改业务内容。

**没有覆盖：**逐项使用 UI 表单建案、登记、写笔录、审核报告的完整手工操作。这些写入由真实 HTTP 脚本完成，审核动作是合成脚本模拟，不能当成专家审阅。没有验收生产身份认证、Unity、W11 或真实多模态推理。

先前一次跨 exec 运行被 PID namespace 所有权检查安全拒绝，未放松校验；同 namespace 首轮浏览器成功，后续加固时瞬时关闭的无关 fd 曾使工具误拒绝，现仅跳过已消失 fd 并仍严格核验监听 inode，最终完整重跑通过。`python -O` 已实测在任何输出目录或服务启动前拒绝。

正常 Linux 主机同一 namespace 的两个终端：

```bash
# 终端 A：输出目录必须不存在，保持前台；结束时 Ctrl-C 清理自身服务
bash tools/stage-demo/run.sh --output /tmp/mcis-stage-my-run --hold
# 终端 B：使用有 Playwright 的 Python 和本机已有 Chrome
MCIS_BROWSER_BIN=/path/to/chrome-headless-shell python tools/stage-demo/browser_check.py /tmp/mcis-stage-my-run/run.json --output /tmp/mcis-stage-my-browser
```

本工具环境每次 exec 使用独立 PID namespace，不能按上述分两次 exec。需在**同一 exec** 内由前台 Python 父进程 `Popen(['bash','tools/stage-demo/run.sh',...,'--hold'], start_new_session=True)` 启动 runner，等待其成功保持提示后执行 browser；`finally` 向自己持有的 runner Popen 发 SIGINT 并 wait，确认 manifest 的 `running:false`。不得凭另一 namespace 的数字 PID 发信号，不得跳过守卫连接旧端口。不要用简单 shell 后台 `&` 后强杀代替优雅清理。
