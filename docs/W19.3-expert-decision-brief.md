# W19.3 给领域专家的裁定摘要

## 当前决定

先不把事故分类逻辑写成产品。保留条件核查设计和测试反例，待专业语义明确；这不是停止整个MCIS或W7并行开发。

## 请先裁定的三个问题

1. **适用框架。** 第一版面向哪个主管机关/法域、哪些船型/船旗与航程？采用哪个有效规则版本及国内实施规定？没有这些，软件不能宣布实际通知或调查义务。
2. **事实关联单位。** 一起擦碰与同船人员死亡在同一案号里，但死亡是否与船舶运营直接关联仍不明。是否允许用一次总的“案件与运营有关”来满足两者？本设计建议不允许；必须把后果、事件/事件序列及证据关系分别记录。具体事件序列与§2.22“涉及”的判断交专家。
3. **主管评价。** 严重环境损害、严重伤害、全损等术语由谁、凭什么材料确认？系统可显示支持材料/未知/冲突，但不能用泄漏数量、经济损失或自由勾选替代专业评价。

## 给专家的交付物

`contracts/W19.3-imo-condition-preview.md` 包含官方来源链接与准确条款、7项问题、拟议事件/后果/证据模型、输出限制和反例验收清单。独立预审单独保留，不视为法律意见或正式专家批准。

## 业务上值得做的最小切片

可追溯的逐条核查表：调查员能看见某条条件由哪一后果、哪一来源声明支持，哪里未知/相反，下一步核实什么。必须显示不能用信息不全作为延迟国家间通知的理由，也不能把没有得到§6支持解释为没有其它调查义务。

在专业定义未确认前，不先做一个“红黄绿事故等级”页面，再靠免责声明补救。纯选择题练习也不冒充业务功能。

## 完成声明边界

本轮仅完成来源研究和设计；无新增运行代码、UI、规则引擎、数据库/审计写入、通知或部署。研究文档单独保存为草稿PR不表示法律批准或实施完成。现有W19知识卡及模板预览不改变。

## 独立预审补充：请用四个合成反例作裁定

| 合成反例 | 两种待裁定解释 | 需要核实的事实/模型选择 |
|---|---|---|
| 同案含明确运营擦碰及关联有争议的死亡 | 后果属于同一事故 vs 只是同一档案 | 死亡与事故/运营的关联及各自证据，不能靠同案号或同eventId |
| 前一事件引发后一事件但记录在两个eventId | 一个事件序列 vs 两个独立发生 | 序列边界、成员及关联断言，不能因ID不同自动排除 |
| 外部海事设施损坏但安全危险有争议 | 符合该分支复合要件 vs 只确认损坏 | §2.9.6的附加要件是否有材料支持 |
| 环境危害的船损关联有争议且国家评价未确认 | 相关分支可能成立 vs 尚缺关键认定 | §2.9.7关联及§2.19评价来源，不能用泄漏数值替代 |
