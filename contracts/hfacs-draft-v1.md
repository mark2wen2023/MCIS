# W18.4 saved manual HFACS classification worksheet

Scope: case-scoped manually authored hypothetical classifications, saved/reopened/edited with optimistic concurrency and atomic local audit. Fixed Draft/ToBeVerified/Investigator; no Confirm/Reject, no responsibility assessment, no person scoring, no agent execution, no ECFC/W11, no report/confirmed-statistics integration. A category title is not a factual allegation. UI instructs work/task/system context instead of premature blame attribution to witnesses or people.

## Method
Read FAA DOT/FAA/AM-00/7 abstract https://www.faa.gov/data_research/research/med_humanfacs/oamtechreports/2000s/2000/0007 ; maritime adaptations Chauvin2013 https://commons.wmu.se/lib_articles/36/ (restricted full article, abstract only) and Celik/Cebi2009 https://research.itu.edu.tr/en/publications/analytical-hfacs-for-investigating-human-errors-in-shipping-accid/ (abstract). These establish adaptation approaches, not equivalence of this project's codes to an official maritime standard. No FAHP weighting or inferential causal claims implemented. Display taxonomyVersion="mcis-hfacs-project/1", taxonomy explicitly project-specific and requiring expert review. Core 32 categories including group/root choices; group drafts must be labelled. Do not label the fifth extension as universal standard.

## Existing C# core
New isolated tools/mcis-hfacs references exactly7 existing source files (Result,Hfacs,CustodyLedger,CustodyEvent,EvidenceItem,InvestigationAudit,Sha256Hex). No source modifications. JSON stdin either {action:"taxonomy"} or {action:"validate",draft:{scope,entries:[{id,categoryCode,description,rationale}]}}. Strict schema, Unicode scalars/UTF8/unknown/duplicate rejection. Scope and descriptions/rationale trimmed nonempty <=1000 chars,1..32 entries, unique ASCII IDs^[A-Za-z][A-Za-z0-9_-]{0,63}$. Category is passed to actual HfacsAnalysis.AddFinding, fixed ToBeVerified,empty evidence/ECFC,ledger null,origin Investigator. Core verifies taxonomy; adapter must not map categories itself. Rationale is human note, no core classification/causality validation. Any failure invalidates entire batch.
stdout {ok:true,result:{coreVersion:"mcis-hfacs/1",taxonomyVersion:"mcis-hfacs-project/1",categories:[{code,name,layer,parentCode,isLeaf}]}} for taxonomy. Validation output {ok:true,result:{coreVersion,taxonomyVersion,entries:[{id,categoryCode,layer,description,strength:"ToBeVerified",reviewStatus:"Draft",origin:"Investigator"}]}}. Protocol/core failure {ok:false,error:{code,message}},exit4. Operational failure nonzero. No confirmation/audit done by CLI, no filesystem business writes. Timeout30s/output256KiB.
