## 使用目标与停止线

调查员在面对不完整、互相矛盾的资料时，需要知道：哪个明确输入支持某条条件、哪项仍需核实、应查阅哪一条原文。产品输出必须是可追溯的条件核查表，不是事故等级、法定义务、责任、法域适用或通知收件人名单。测试与当前演示只准合成材料；不得从实际案件自动读取或通过知识卡公开。本次不设计保存、导出、通知、期限计算、自动抓取或模型推理。

关键区分：开发者可核验布尔组合与输入绑定，不能替代主管机关或专家作事实/法律认定。合成演示不是实际调查可用性或法律准确性认证。若专家无法确认下面的归一化事实模型，停止运行实现，只保留问题清单。

## 必须先由专家裁定的问题

Q1 目标业务法域、船旗与船型、航程，以及适用版本/国内实施规定是什么？本提案恒定返回 `legalApplicability: undetermined`，不让用户勾选一下就视为已确定。

Q2 调查员是否可以分别为每个§2.9后果声明“本后果与船舶运营直接关联”？单一全案“运营有关”布尔值可能把一个相关擦碰和一个无关死亡错误连在一起。建议必须事件/后果同一性绑定；当前不推断因果关联。

Q3 §2.22的“涉及”关系与§2.9“直接关联”是否足以用同一事件键表示？多船、多事件、岸上死亡、推定损失/全损及后发现死亡怎样归属？未裁定前不应从一组后果自动产生very-serious条件结果。

Q4 §2.18“超过72小时”与“七日内开始”的边界、时区与伤情证据由谁确认？§2.19由适格国家作评价应怎样记录、何种资料算已确认？不以船员填写的损失金额或泄漏吨数替代。

Q5 海域输入与沿岸国关系如何核验？EEZ不是领海，不能按地理最近国家推断。实质利益国§2.20含需主管调查国判断的类别，当前不得自动枚举国家、机构或通讯地址。

Q6 故意伤害排除的不确定/冲突怎样展示？不得将排除提示解释为无需调查、无需通知或无安全问题；不得遮蔽原始伤亡线索。

Q7 仅提供§5/6核查是否容易被误读成完整法定义务清单？需包含§5.3醒目不延迟说明和§17/其他法规未评价提示；不能用绿色“无义务”。

## 拟议数据模型（等专家确认后才冻结）

根：固定profile、`dataMode: Synthetic`、最多8个合成事件。每个事件有受限唯一eventId；每个后果有唯一factId和该事件内关联的来源条目（sourceId、合成标题、页/段定位），可含多个相反断言，不允许自动按最后输入覆盖。

事实状态：`asserted_yes / asserted_no / unknown / conflict`。这些是人工声明状态，不是系统核实事实。每个断言包含断言者角色标签与合成依据定位；不接收真实姓名、自由上传或URL内容抓取。缺失永远unknown，空数组不是false。列表与输入有工程上限，不是法律阈值。

最低条件组：
- 每个§2.9列举后果分别记录出现状态与运营直接关联状态，不能用无关联的其它事件补足。
- 故意伤害排除按同一事件记录；unknown/conflict不得推为未排除。
- 损坏、严重伤害、环境评价分别为专家确认的术语状态，不把简化数值算法冒充术语判断。面板展开显示原文定位及核实问题。
- 全损与推定损失/弃船分开；死亡与严重伤害分开；严重环境损害与潜在环境损害分开，禁止相互提升。
- 海域仅为同一事件的人工声明（公海、EEZ、领土含领海、未知、冲突）；不做坐标推断。国家/调查协议不自动判断。

## 拟议输出

始终 `persisted:false`, `reviewRequired:true`, `legalApplicability:undetermined`, `notificationSent:false`。不提供classification / dutyRequired / responsibleState / recipients / deadline字段，不写入case/report/audit/知识卡。

每一行：条款编号、官方URL、印刷页、受检查的条件表达式、输入factId/sourceId列表、尚未解决项、逐项状态及解释。保留全部矛盾与未知输入；不因另一分支成立而藏掉未明伤亡。显示“给定合成声明支持这一条件组合”而非“已满足法律义务”或“事故已定级”。

三种解释性状态加冲突：`supported_by_input / not_supported_by_input / undetermined / conflicting_input`。否定只表示该精确组合不受本输入支持，不表示现实不存在或没有其它法规义务。

候选语义（未获专家裁定，不实现）：
1. §2.9：同一事件存在至少一个列举后果及其直接运营关联，且未落故意伤害排除；冲突、缺失按上面原则保留。
2. §2.10：不能把“§2.9未得到支持”当作“确定不是§2.9”；仅当相应排除条件充分明确时评估，否则undetermined。
3. §2.22/§6：按Q3明确事件/后果关系后才评估，不由船名或案号自动拼接。
4. §5.1/2：以§2.9条件及同一事件海域为前提，仅显示条文规定的国家角色，不生成具体收件人；无论信息完整性状态如何都展示§5.3。

不采用数字严重度分数、不发绿灯、不给“免调查/免通知”按钮。全部输入改变即时失效旧输出；关闭/导航/身份改变清空内存。若未来接后端，必须另订原文权限/严格入参/无副作用及异步失效合同。

## 独立预审后的未决修正（优先于上述候选模型）

独立工程/来源一致性预审见 `tests_acceptance/W193/PRE_REVIEW.md`，不是具有资质专家的法律批准。预审要求本轮保持设计，不冻结或运行复合条件流水线。

- 上面“同一事件”的要求过强且不充分，暂撤回作为规则约束。原文容许事件序列，按不同eventId强行隔离可能漏掉真实关联序列；给两后果同一eventId也不能证明关联。需要分别记录人工提出的 occurrence/sequence 边界、成员与后果关联断言、来源和竞争解释，待专家裁定后再定义规则。不能自动拼接，也不能自动否定跨事件关系。
- §2.9.6的附加安全危险要件、§2.9.7的船舶损坏关联要件及§2.10危险/若不纠正的危险要件尚未在候选字段中明确，因此当前模型不完整，七个笼统后果框不能进入实现。
- 四值聚合还没有真值表。应分清单条断言、材料完整性、冲突和某个分支的支持度，不用一个全局结果覆盖这些维度。角色标签或“专家确认”字段只是来源声明，不认证主管机关/专家身份。空输入、相反声明、重复来源、范围不同、材料更新和撤回都须在合同与测试中明确。
- 第5章提示必须写明国家间通知，而非船长国内报告流程；§5.3及§17/其他规则边界在未填完整表单时也可见。引用§7.5时补印刷页12。不存在等待本工具给出结果才采取行动的门禁。

这些是设计缺口，不是已发生的产品缺陷；本轮没有规则代码，也没有“法律验收通过”结论。
