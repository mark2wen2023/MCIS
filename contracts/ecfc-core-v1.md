# W11 new manual ECFC core adapter, version 1

New implementation against main 3aba2bf; no previously interrupted implementation or historical tests are reused. Method source: repository thesis §2.5 table 4 (its cited Sklet 2002 is not independently revalidated here), ARCHITECTURE §4.9.1 and unchanged project EcfcValidator. The original authority is a charting method, not a legal compliance standard or proof of causality.

## Protocol
stdin UTF-8 JSON <=131072 bytes, exactly `{action:"validate",draft:{scope,nodes,edges}}`. No arguments, duplicate/unknown keys, invalid Unicode, nonfinite numbers or excess nesting. scope trimmed nonblank <=1000 Unicode scalar values. Nodes 0..40, edges 0..80.
Node exact `{id,kind,text,timeSeconds,lane,isPrimaryIncident,evidenceIds}`: ASCII id `[A-Za-z][A-Za-z0-9_-]{0,63}`, unique within nodes; kind Event/Condition; text trimmed nonblank <=1000 Unicode scalar values; timeSeconds finite number in [-315576000,315576000] or null, relative to case epoch (unknown stays null); lane integer -5..5; isPrimaryIncident boolean; evidenceIds 0..8 unique `EV-[0-9]{3,}` strings. Registration existence/permissions are HTTP service responsibilities. Edge exact `{id,from,to}`, same id format, unique edge ID; endpoint node IDs must exist. Duplicate ordered pairs, self-edges, any cycle and Event→Condition are structural refusal. Empty/incomplete charts are accepted drafts.

stdout `{ok:true,result:{coreVersion:"mcis-ecfc-draft/1",nodes,edges,issues}}`. Nodes preserve fields and order, add `isPresumptive:true`; all nodes remain hypotheses even if evidence IDs are supplied. Edges preserve IDs/endpoints and add kind Sequence/Influence and bold boolean derived by unchanged core DeriveEdgeKind. Issues exact `{code,isError,message,nodeId,edgeId}` from unchanged core Validate, with nullable IDs. `isError` labels a project diagnostic, not save failure. Domain/protocol refusal `{ok:false,error:{code:"ECFC_INPUT",message}}`, exit 4; internal failure generic ECFC_INTERNAL, exit 1. No business persistence or source fetching occurs in this CLI.

## Structural versus methodological/professional review
Structure acceptance only guarantees this bounded serializable directed acyclic graph profile. It does not prove events, causal links, responsibility, chronology, compliance or evidence authenticity. Missing/multiple incident markers, absent times, missing main-sequence connections, text/quantification suggestions are returned without blocking draft storage. Presumptive nodes must render dashed rectangles (events) or ellipses (conditions). Event arrows are solid; condition arrows dashed; lane-0 event arrows bold. A sequence arrow is not proof of causation.

The original validator's word-list/English-suffix heuristic is not linguistic understanding; it can miss valid phrasing or accept inappropriate text. It only explores condition-to-event links up to two steps. It sorts main events by time then ID and treats missing times separately, not a full temporal consistency analysis. This slice has no quantities dictionary so quantification advice persists even if prose includes a number. Architecture aspirations (full branching/time monotonicity checking, full automatic layout, drag editing, Unity cards) must not be inferred from this output. Fixed presumptive status is intentionally more conservative than architecture's optional evidence-based assertion flag.

## D2 output budget correction
Default JSON escaping is retained. A valid 25-node chart with 1000 emoji per node uses roughly 104KiB input but over 256KiB JSON output (surrogate-pair escapes). HTTP adapters must allow **1048576 output bytes**, including newline, rather than confuse this legal chart with unavailable core. The CLI also explicitly enforces this same bounded stdout ceiling; it does not truncate.

Conservative bound for the fixed protocol: 40 node texts ×1000 Unicode scalars ×12 escaped bytes =480000; all other node properties at most40×1000=40000 bytes (including eight ≤64-character ASCII evidence IDs); edges at most80×400=32000 bytes; envelope reserve1024. On structurally accepted input, the unchanged validator has at most201 diagnostics: at most five per non-main node; a main event has at most three, and at most m−1 additional main-sequence warnings for m main events, plus one graph incident-count warning. Each diagnostic is below2048 escaped bytes, including fixed messages and ASCII IDs. Total reserve964672 bytes <1048576. Bounds are engineering protocol limits, not professional thresholds. Future changes to fields, node limits, validator messages or diagnostic loops require re-evaluation.

D2 regression preserves the previously failing legitimate input and verifies output actually exceeds256KiB while remaining within1MiB. A separate40-node test exercises the201-diagnostic maximum. Implementation self-tests are not independent acceptance.
