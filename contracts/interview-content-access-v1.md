# W5.2a Interview full-content isolation

Existing endpoint paths remain unchanged. This is conservative full-content access isolation, NOT complete redaction, authentication, legal signature or factual verification. Local header identities are self-reported.

## Authorization
Only Investigator/LeadInvestigator may access original interviews and their derived text. Every existing policy category must explicitly be ReadOnly/ReadWrite; any applicable field rule, unknown or malformed policy denies. Writes additionally require testimony=ReadWrite. Default Investigator is intentionally denied; default Lead remains eligible. No automatic policy or role changes. The policy validator follows W16.2 but error messages refer to interview content.

All case-specific interviews and interview-compare endpoints, redaction preview of interviews, and interview-bearing agent drafts/prompt previews/extraction/application are covered. Source evidence, if bound, must exist in the same case and be currently visible; missing/restricted references deny without detail. A registered hash is metadata, not a fresh byte check or proof that transcribed text matches an original. Legacy sourceSha256 without a resolvable source is not a verified original.

General audit outputs containing Interview/statement/crossCheck identifiers or interview/statement actions, including raw audit JSON markers, require full interview access. Package export with testimony, interview-bearing agent drafts or interview audit requires full access, including residual audit-only cases. Legacy package import with nonempty testimony or interview-bearing drafts is rejected before mutation: this endpoint is not an authorized path to restore transcripts and their policy. W8.5 already rejects nonempty testimony.

## Transactions
Explicit SQLite BEGIN IMMEDIATE precedes policy and interview reads/writes in protected routes, serializing all same-document writers and preventing concurrent policy commits while preparing output. Read-only means no business-row changes, not no lock. Existing agents review/apply transactions are reused, not nested. This cannot retract bytes already delivered. Denials do not append audit, render files or invoke models. Success/error responses are no-store with no sensitive exception details.

## Legacy mutation restrictions
Create accepts only unsigned empty drafts. Supplied turns/statements/crossChecks must be empty; signed must be false or absent. Client-supplied sourceSha256 is rejected. An optional evidenceId must resolve in the same case and be visible; its stored SHA is copied by the server. startUtc remains required and must be valid UTC: unknown time is rejected, never invented. Existing recordId rules remain. No new idempotency contract in this slice.

All mutation of a signed interview is rejected, including add turn/statement, review, compare decisions/revisions/rechecks and agent application. No unlocking/re-signing feature is added. Reopening a page only reads stored state. A separate W5.2b will define bounded manual creation/append, request receipts and optimistic digests.

## Boundaries/tests
Synthetic seed=False only. Reproduce original raw-derived disclosure, injected signed/Confirmed state and concurrent lost append, then retain regression assertions proving denial/no loss. No professional core or W11 modifications. Confirmed remains workflow status. Existing field masking may still operate on allowed responses; this is not a promise of universal redaction.

Source conflict: where evidenceId is bound and sourceSha256 is nonempty, mismatch with current registered SHA returns 409, never silently rebinding. A legacy hash without a source is not verified provenance. All signed records are read-only in this slice, including the existing signed demonstration records; fixtures must not silently change production seed status. Unsigned synthetic fixtures may exercise old mutation assertions.

Method context only: IMO A.1075(28) §5.5.4 separates collection/analysis and §§5.8.1–3 discuss interview planning, informing witnesses and clarifying/checking written records (https://wwwcdn.imo.org/localresources/en/KnowledgeCentre/IndexofIMOResolutions/AssemblyDocuments/A.1075(28).pdf). MAIB witness §4 is UK-specific methodological context (https://www.gov.uk/government/publications/witnesses-following-a-marine-accident/maib-interviews-witness). This security patch does not make records legally signed or professionally validated.

Compatibility: direct AgentService input/extract and interview-bearing draft submission now fail the original-content gate. Only a qualifying investigator may trigger the existing local-model extraction workflow. Mandatory LLM egress masking in agents.extraction is retained independently; a permitted caller does not disable it. This is not an assurance that every possible personal fact is automatically redacted. Non-interview agent targets keep their existing authorization; orphaned agentDraft audit events cannot be safely classified and require the original-content gate.

Operational limitation: SQLite BEGIN IMMEDIATE reserves the writer for the entire database, not only one transcript. Protected reads/export preparation hold this reservation. Model invocation does not: a short pre-send transaction authorizes the exact prompt and records the document/evidence snapshot digest, then releases before invoking the model. A second short transaction checks current authorization, full source snapshot and prompt digest before saving any draft. The model-call authorization linearizes at the last pre-send transaction; revocation afterward cannot recall already authorized outbound bytes or cancel the call instantly. Revoked or changed-source results are not saved or returned. Protected content preparation still uses database-wide reservations, not scalable per-record locks. Stub tests verify call ordering and mandatory egress masking, not real model connectivity. Initial authorization denial has no audit side effects. If an earlier authorized phase already committed agent.run.started, a later policy recheck denial preserves that historical entry and does not append a new failure event on the denied path.
