# W19 knowledge archive v1: isolated read-only historical collection

## 1. Scope and non-goals

This slice exports the complete **current online** `knowledge_cards` and `knowledge_audit` snapshot, including Candidate, Published, Rejected and Withdrawn. Imports create an independent immutable historical archive, never online cards. Historical Published/approvals remain unverified historical labels, not a current permission to publish, an identity verification, or a fresh review. No candidate derivation, online restoration, merging, deletion, external retrieval, model call, source-file upload or automatic disclosure is included. A separately specified forward-only audit capture addition below preserves new W19 create/review operations without changing their existing state machine or original audit-line format; archive import itself performs no online state transition.

Existing archives are deliberately not recursively included in a new online export. Each saved original archive can be downloaded separately. This is not a complete system backup, a backup of all previously imported archives, or a claim to restore missing historic data. Knowledge content contains source URLs/excerpts/locators/rights notes, not the referenced external documents; no URL is fetched.

**Existing information loss:** current W19 withdrawal replaces reviewedBy/reviewedUtc/reviewNote/approvals from publication. Its audit records status, actor, role and note, but not the three publication approval booleans or historic full card snapshots. Archive preserves everything currently present without inventing overwritten metadata. Historical publication's three approvals cannot be reconstructed or freshly certified. All current bodies, metadata and original audit strings are retained.

## 2. Authorization and snapshots

Every export, preview, save, list, detail and original-byte download requires exactly LeadInvestigator. Gate before archive lookup/body inspection; others receive generic403 without existence/count/content details. This is local-role-header mode, not authentication, verified personal identity or production multi-user access control. Knowledge is global, never scoped or authorized through a case policy; case selection cannot alter results. All responses, including controlled errors and unexpected500, use Cache-Control:no-store and no content-bearing error details.

SQLite only for this slice. Online export obtains WRITE_LOCK then real BEGIN IMMEDIATE before selecting either table, matching existing W19 writers' lock order; both tables share one snapshot. Validate and serialize inside that short local transaction, then end it before sending bytes. Export does not append online knowledge audit or alter any card. No network/model work occurs while locked. A read here can reserve the whole SQLite writer, not merely knowledge rows. Concurrent supported writers serialize; bytes already delivered cannot be revoked. No claim of production authentication or universal multiworker correctness for unrelated routes.

## 3. Transport and exact envelope

Single UTF8 JSON file, no ZIP, compression, Base64 wrapper, attachments or executable objects. Maximum raw bytes 8MiB (8*1024*1024), depth32, cards1024, audit lines4096, full audit snapshots4096. Stream reject before extending beyond cap, then strict JSON: reject duplicate keys at any depth, NaN/Infinity, invalid UTF8, BOM, lone surrogate and trailing content. Unknown version/fields reject; no coercion, truncation, dropping or repair. Resource caps yield413 KNOWLEDGE_ARCHIVE_BUDGET; schema/semantic errors422 KNOWLEDGE_ARCHIVE_INVALID. Bool is not an integer.

Exact root:
```
{format:"MCIS-KNOWLEDGE-ARCHIVE",version:1,exportedUtc:"...Z",
 cards:[{order:1,cardId:"KC-<32 lowercase hex>",status:"Candidate|Published|Rejected|Withdrawn",kind:"Case|Challenge|Method",searchText:"...",tagsText:"...",doc:{...}}],
 audit:[{seq:1,line:"<original database line string>"}],
 auditSnapshots:{coverage:{mode:"legacy-only|from-sequence",firstSeq:null,priorHeadSha256:"<hex64>"},items:[]}}
```
`order` is consecutive1..N in original Card.id ascending order, preserving ordering without copying database integer primary keys. cardId globally unique in this envelope. No source DB id is an online restoration key. Audit seq consecutive1..M, exactly agrees with parsed line seq. Empty cards+empty audit is valid; nonempty audit referencing absent cards is invalid. `exportedUtc` is metadata, not evidence of when content was investigated or authenticity.

All UTC metadata uses actual valid Gregorian yyyy-MM-ddTHH:mm:ssZ years1900..2100, original string preserved. These are engineering compatibility limits, not investigative rules. No silent precision conversion. Preserve current original doc values, source strings, array order, and original line characters. Original SQL JSON whitespace/physical SQLite bytes are not available through the ORM and are not promised. Imported raw envelope bytes, including their JSON whitespace, are retained exactly.

## 4. Card semantics and derived columns

Candidate doc exact keys: cardId,status,content,contentDigest,createdUtc,createdBy. Other statuses additionally require reviewedUtc,reviewedBy,reviewNote,approvals; no extra keys. IDs/status agree with row. content follows the existing knowledge-card schema and existing validate_content rules (public HTTPS address validation without fetch; Synthetic has no URL; tag uniqueness after strip/casefold; text/control/Unicode bounds). Its canonical UTF8 compact sorted JSON <=32768bytes, SHA256 equals contentDigest. All original content strings are preserved. kind equals content.kind.

`tagsText` must equal `|` + joined stripped/casefolded tags + `|`; `searchText` must equal newline join of title,summary,body,applicability,normalized tags then casefold. Preserve these columns exactly only after equality verification; corrupt indexing is rejected, not silently rebuilt. createdBy/reviewedBy are nonblank strings <=160codepoints, valid Unicode without control characters. reviewNote nonblank <=2000, normal existing newline/tab allowance. These actor limits are engineering envelope limits; any existing out-of-budget row rejects the entire export rather than dropping actors.

approvals exact sourceVerified/rightsVerified/releaseApproved booleans. Published requires all true; Rejected/Withdrawn preserve their actual booleans without interpreting them as publication approval. Candidate must have no review fields. Rejected and Withdrawn do not become public merely because their source type says Public.

## 5. Original audit chain and card lifecycle

Every original `line` is UTF8 <=32768bytes, strict JSON object with exact keys seq,utc,operator,role,cardId,action,before,after,note,prevHash. Preserve the string, not parsed/reserialized replacement. Sequence starts1; first prevHash is64zeroes; subsequent prevHash equals SHA256 of previous original line UTF8 (no added newline). Validate operator as above, note <=2000 (create empty), role allowed by action, timestamps valid, hashes lowercase hex64. Hashes establish internal consistency only, not external signature/authenticity or truthfulness.

Per card state machine, interleaving cards allowed:
- knowledge.create once, role Investigator|LeadInvestigator, before empty string, after equals contentDigest, note empty. No prior card event.
- knowledge.published: LeadInvestigator, Candidate→Published.
- knowledge.rejected: LeadInvestigator, Candidate→Rejected.
- knowledge.withdrawn: LeadInvestigator, Published→Withdrawn.
No unknown action, duplicate create, orphan event, skipped/repeated state transition or postterminal action. Every card must have a create event. Its createdBy equals create operator; final doc status equals event-replayed state. For reviewed cards, final reviewedBy/reviewNote match last review operator/note. Content digest is constant: no edit action exists. `createdUtc` versus create event utc and `reviewedUtc` versus review event utc are separately generated; validate and preserve each, do not require equality or impose invented time-difference limits. Current Published all-three approvals are checked from doc, but past Published approvals of Withdrawn are unavailable and explicitly not reconstructed. Chain verification does not certify factual approval.

## 6. Historical persistence and idempotency

New isolated table `knowledge_archives`: archive_sha256 primary key, raw_bytes immutable BLOB, imported_utc, imported_by, imported_role, byte_length, card_count, audit_count, audit_head_sha256. All stored columns are exact schema; imported_role LeadInvestigator. Database append-only triggers prevent update/delete. This table is excluded from online W19 searches, details, suggestions and audit; no online row is inserted, updated or removed. Storing raw bytes and metadata in a single SQL transaction avoids file/SQL partial commit. No separate file path, raw SQL credentials or activation token is imported. Archive import metadata describes this local save, not original authorship.

SHA256 of exact input bytes is archive identity and idempotency key. Two byte-identical imports create one row; first commit201 replayed:false, later same-bytes200 replayed:true. Same digest with different stored bytes or inconsistent stored metadata fails409 KNOWLEDGE_ARCHIVE_INTEGRITY, never overwrites. Distinct bytes representing equivalent JSON are distinct archives by design, not silently coalesced. requestId/actor or online audit replay credentials do not exist in the package. Save requires explicit expected raw digest, preventing a changed preview body from being saved unintentionally. A lost response remains unknown until authorized GET by digest;404 is not proof of an earlier transaction's noncommit if infrastructure state changed.

Stored original bytes are rehashed and fully validated before history detail or download; corruption rejects409 without returning content. Recompute summary to check stored metadata. Never fall back to a partial parsed card. Concurrent saves use WRITE_LOCK→BEGIN IMMEDIATE and unique digest key; rollback/commit failure leaves no partial archive or online effect. The first saved actor/time remain immutable on replay. No cross-role permission is gained from old metadata.

## 7. API (new routes only)

Prefix `/api/v1/knowledge/archives`.
- GET `:export` (full path `/api/v1/knowledge/archives:export`):200 application/json attachment, exact validated envelope bytes, X-Sha256 raw hash. Empty online library supported. No history row created.
- POST `:preview`:application/json raw envelope,200 summary. No persistent writes.
- POST prefix itself: same raw envelope plus required `X-Archive-Sha256` lowercase hex64; server recomputes and compares, mismatch409 KNOWLEDGE_ARCHIVE_CHANGED. Save201 or replay200.
- GET prefix: paginated metadata only, limit1..50 default20, offset0..10000, stable importedUtc descending then archiveSha256 ascending, `{items,total,limit,offset}`. Lead only.
- GET `/{archive_sha256}`: full validated historical envelope and metadata, never online doc API.
- GET `/{archive_sha256}/content`: exact original bytes, application/json attachment filename `knowledge-archive-<sha>.json`, X-Sha256; verified before successful response. No source URL fetch.

Summary exact `{profile:"MCIS-KNOWLEDGE-ARCHIVE-1",archiveSha256,byteLength,cardCount,auditCount,auditHeadSha256,scope:"current-online-library-snapshot",restoreMode:"isolated-read-only-history",identityMode:"unverified-self-reported"}`. Empty audit head64zeroes; otherwise SHA256(last original line).
Saved metadata exact `{summary,importedUtc,importedBy,importedRole}`. Save response `{archive:<saved metadata>,replayed:boolean}`. Preview response summary only. Detail response `{archive:<saved metadata>,envelope:<validated original parsed root>}`. List items saved metadata. Statuses are solely envelope historical values; APIs must not add current release approval. Metadata limits derive from the byte/count caps above.

Errors:403 FORBIDDEN before lookup;404 KNOWLEDGE_ARCHIVE_NOT_FOUND;409 KNOWLEDGE_ARCHIVE_CHANGED / KNOWLEDGE_ARCHIVE_INTEGRITY;413 KNOWLEDGE_ARCHIVE_BUDGET;415 UNSUPPORTED_MEDIA_TYPE;422 KNOWLEDGE_ARCHIVE_INVALID. Invalid digest path/header422 without lookup. Unknown exceptions500 generic/no-store with rollback, no raw content/path/DB diagnostics. No promised automatic retry; caller keeps exact bytes and digest for retry. Raw body parsing asynchronously bounded; synchronous DB transaction helpers run in worker thread, session created/closed inside helper, no ASGI loop lock wait.

## 8. Acceptance and explicit limits

Synthetic-only real HTTP tests: all four states and all three card kinds; empty library; source content/control limits; unknown/duplicate/nonfinite JSON; all counts/bytes/depth; original audit whitespace/string preservation; strict chain/order/card reference/state/digest/index checks; final review metadata matches while distinct valid timestamps remain accepted; withdrawn lost approval information not fabricated. Every role across every endpoint, denied invalid IDs no existence leak, no-store all outcomes. Export concurrent online create/review yields one coherent old/new snapshot, not mixed columns/chain. Duplicate same-byte saves race to one immutable row. Faults during save/commit rollback every new row, no online writes. Stored blob tamper fails detail/download, exact bytes survive source→history→download across databases. Public online list/search unchanged even when a historical envelope contains Published. List caps/order and responses bound; no external fetches. Explicitly prove original online cards/audit byte strings unchanged by preview/save/read/download.

This v1 archives current W19 cards/audit and the explicitly defined forward-only snapshot/epoch tables, not package/case evidence, online DB integer identities, source websites, prior missing review snapshots, or earlier imported archive collections. Future online knowledge schema/action changes must require a new supported version or reject; do not quietly accept unknown columns/doc fields. A later candidate derivation workflow requires a separate contract, new identity and new manual review, and is not implemented here.


## 9. Forward-only full audit snapshots (design addition; no historical backfill)

New global append-only tables:
- `knowledge_audit_snapshot_epoch`: singleton key1, first_seq integer>=1, prior_head_sha256 hex64. Initialize in the first successful newly instrumented create/review transaction, using next online audit seq and the preceding original line hash (zero for empty chain). No separate startup migration writes, no historical reconstruction. Failure rolls back marker too.
- `knowledge_audit_snapshots`: seq primary key, audit_line_sha256 hex64, card_id, before_doc nullable JSON, after_doc JSON. Store exact semantic full documents, including all approval booleans and review metadata. Foreign correspondence is validated, not assumed from integer proximity. SQLite triggers forbid update/delete on both tables.

Every newly instrumented create AND review appends its snapshot in the **same existing WRITE_LOCK→BEGIN IMMEDIATE SQL transaction** as the card and original audit line. Create before_doc=null; after_doc is complete Candidate. Review before_doc is complete prior doc, after_doc complete new doc. Refactor audit helper only to return the inserted event/seq for linkage; original event shape, original line construction and old `/audit:verify` remain unchanged. No model/network call. Snapshot failure rolls back card, event and marker. No backfill of pre-enable events. Deployment requires a single supported upgraded writer version; older parallel writer processes may produce coverage gaps, which validation rejects rather than pretending completeness.

Envelope auditSnapshots is required in this archive version and has exact coverage/items keys. In a source DB with no epoch and no snapshots: coverage `{mode:'legacy-only',firstSeq:null,priorHeadSha256:<head of entire exported original audit or zero>}`, items empty. This means full-doc historical snapshots unavailable, not an approved/verified legacy record. Any snapshot row without epoch is corruption. With epoch: coverage `{mode:'from-sequence',firstSeq:<epoch>,priorHeadSha256:<epoch>}` and items ascending seq, each exact `{seq,auditLineSha256,cardId,beforeDoc,afterDoc}`. Require firstSeq<=auditCount, priorHead matches original preceding line/zero, and exactly one snapshot for every event from firstSeq through auditCount. No gaps, duplicates, unknown rows or snapshots before firstSeq. Empty online history cannot claim a populated epoch. Imported envelope coverage is an unverified historical claim whose structural consistency can be checked; hash is not proof that a malicious author did not strip snapshots and label a package legacy-only.

Every snapshot validates full document schema/content digest/approval rules from §4, card ID and original event association. auditLineSha256 hashes the exact associated original line. Create afterDoc.createdBy matches event.operator, Candidate and digest match create event; before null. Review before/after status match event before/after, actor and final review note match afterDoc and event; content and creation fields stay exactly unchanged; only status/reviewedUtc/reviewedBy/reviewNote/approvals may differ. A Published afterDoc has all three approval booleans true; a later Withdrawn snapshot retains the original Published approvals in beforeDoc without replacing them. For each card, later beforeDoc must equal earlier captured afterDoc, and final captured afterDoc equals current card.doc. At a card's first captured review with only legacy preceding events, beforeDoc must agree with existing preceding lifecycle state and immutable content/creation fields but is labelled first-observed, not independently verified against an unavailable earlier snapshot. Never claim old missing approvals newly established by a captured copy. Separate event/document UTC values are preserved, not forced equal.

Summary adds exact `auditSnapshotCount` integer and `snapshotCoverage:{mode:'legacy-only|from-sequence',firstSeq:null|integer,priorHeadSha256}` to §7 shape. History views display missing legacy coverage explicitly. The archive's own stored bytes contain snapshots; no online snapshot or epoch rows are inserted when saving history. A historic Published snapshot remains historical, and cannot grant present-day release rights. Schema must reject unknown future snapshot version/fields; no silent omission.

## 10. Explicit global-table integration and tests

New `knowledge_archives`, `knowledge_audit_snapshots`, `knowledge_audit_snapshot_epoch` are global, not per-case. After explicit cross-module approval, narrowly add these three exact names to the existing working-record archive GLOBALS exclusion set. Do not change `.mcase` format or hide unknown tables generally. Case archives do not include global knowledge/history; new knowledge exports include online cards/audit/snapshots/epoch but not previously saved `knowledge_archives`. These separate scopes must be stated in UI/contracts/REQUESTS. This compatibility edit requires a regression showing populated new globals do not block an otherwise supported case archive, while unknown populated tables still reject.

Additional synthetic tests: create and each review capture complete original before/after with three approvals, old line format/chain unchanged; before-enable history yields explicit missing coverage, never fabricated snapshots; publication→withdrawal retains first approvals in immutable snapshot; snapshot/marker write fault rolls back all online rows; concurrent reviews only one accepted snapshot; orphan/missing/duplicate snapshot, wrong line hash/card/actor/lifecycle/digest/current doc, tampered epoch/head and count limits reject. Export races with new review yield coherent card/event/snapshot/epoch states. Legacy-only and mixed-era archives save to independent history and download original bytes without creating online cards/events/snapshots/epoch. No claim of capturing writes from old concurrently running software.


## 11. Determinate pre-save refusal versus unknown persistence outcome

Only POST `/api/v1/knowledge/archives` may return `X-MCIS-Write-Outcome: not-committed` for a refusal raised entirely before any persistence transaction begins. Exact allowed status/code pairs:403 FORBIDDEN,415 UNSUPPORTED_MEDIA_TYPE,413 KNOWLEDGE_ARCHIVE_BUDGET,422 KNOWLEDGE_ARCHIVE_INVALID,409 KNOWLEDGE_ARCHIVE_CHANGED,503 KNOWLEDGE_ARCHIVE_UNAVAILABLE. These cover role/backend availability, media/raw-size/JSON/schema/semantics, actor and expected digest prechecks. Clients may release a pending save lock only with this header AND a listed matching status/code. A generic4xx, missing header, network failure or malformed response does not prove noncommit. Dependency failures outside this endpoint's precheck handler are not labelled. Once the persistence helper starts, no error receives this marker, even a rollback-known integrity409 or commit500. Success/replay are verified through their normal exact response. Read/preview routes never label a save outcome. Tests include a simulated failure after actual commit: saved history remains recoverable and no not-committed marker may be attached.

Online snapshot capture uses aggregate seq/epoch/coverage checks, original tail hash and current-card captured-before relation under the existing transaction, without serializing the entire online library per write. Full historical semantic validation and archive engineering caps are applied at export/import, not as new online card or actor limits. Legacy or oversized online libraries can still undergo their existing valid publication/withdrawal operations even if they cannot fit this archive version. This is not a claim that every previously corrupted historical field is discovered on each online write.


Same-byte save replay additionally requires the original importedBy and importedRole to equal the current declared operator/role. A different declared subject receives409 KNOWLEDGE_ARCHIVE_OWNER_MISMATCH without previous metadata and without the not-committed marker (lookup is inside the persistence transaction). An authorized Lead may separately GET that archive as a read, but this is not proof that their own pending save committed. These headers and outcome markers operate within the existing local application trust boundary, not cryptographic authentication; a caller able to forge role/operator headers can impersonate that declaration.
