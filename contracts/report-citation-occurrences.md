# PDF/DOCX citation occurrence trace

The existing ordinary and bundle renderers now annotate each rendered sentence with a positional marker `S<section ordinal>.<sentence ordinal>`. Each citation occurrence is labeled `C<section ordinal>.<sentence ordinal>.<citation ordinal>` both next to the sentence and in an appended trace list. Positions are one-based and scoped to that particular report snapshot; they are not stable entity IDs across regenerated/reordered reports. Original sentence IDs and section IDs are retained separately in the appendix. Duplicate IDs or duplicate citation values remain separate occurrences.

For each sentence the appendix preserves sectionId, sentenceId, sentence status, sourceStatus and missing declaration. For every citation it preserves kind, id, registration, unregistered, needsReview, href and sourceRef exactly as JSON scalar display values. Literal whitespace inside JSON values is displayed as Unicode escapes (for example `\u0020`) to prevent PDF layout from collapsing distinct values. Absent optional fields display `not supplied`, distinct from false, empty string or null. A sentence without citations explicitly says none were supplied, rather than implying supported content. Fallback legacy section text has a positional sentence marker and an explicit absent sentenceId; no original sentence is invented.

The existing References summary still collapses exact identical declarations only; distinct flags/status declarations are no longer collapsed. The occurrence list never deduplicates. Source URLs remain text, with no fetching, active hyperlinks, embedded resources or evidence registration. Ordinary PDF/DOCX still exports from the supplied report snapshot and does not resolve live sources. Labels are declarations, not verification of citation support, source freshness, bytes, author or facts. Source text is not rewritten. Existing disclaimer/Draft behavior and access/audit/download paths remain unchanged.

No new schema, request option, database field or model call. Byte-level report/output binding continues to use the existing explicit download bundle; the new positional trace is not a replacement for that bundle or a signature. PDF/DOCX binary bytes can vary between repeated renders; positional trace metadata is deterministic for the same snapshot. Output format changes are intentional and do not imply equality with previously downloaded bytes.
