# Timeline interval safety (TL-INTERVAL)

Applies to existing GET `/api/v1/cases/{case_id}/timeline` and POST `/api/v1/cases/{case_id}/timeline/events`.

- Seconds are relative to caseEpochUtc, independent of display timezone; negative values are valid.
- GET fromSec/toSec must be finite if supplied, and fromSec <= toSec. Bounds are inclusive. No tolerance padding or rounding is applied at filtering time.
- POST timeSec must be a finite JSON number (not boolean/string). endTimeSec may be omitted/null, otherwise finite and >= timeSec. Both must be representable by existing UTC conversion. Invalid ranges return HTTP 422 / `TIMELINE_RANGE_INVALID` before writes.
- Null/missing end means a point. Zero is a real endpoint, not null. Equal endpoints are valid.
- UTC is generated by existing server conversion; its existing millisecond formatting is unchanged. No alignment, offset or confidence estimate is inferred.
- `presumptive`, `confirmed`, evidenceIds and sourceLabel are unchanged. `confirmed` is an existing user workflow flag, not automatic proof of truth.
- Historical stored data is not modified or migrated. Legacy malformed intervals can still require manual review.
