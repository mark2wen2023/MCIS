# W8.4 案件文字档案编辑

## 原设计与边界
原型 02（案件基本信息录入）、ARCHITECTURE §4.1 CaseManager/CaseMetadata 与 R-03 编辑审计是依据。本片让占位 `#/case?case=...` 能读真实档案并保存人工文字修改，不实现完整案件配置。

只允许修改 title、placeName、leadInvestigator、agencyName、summaryNotes。caseId/schemaVersion、时间/纪元/时区、坐标/高程、事故类型/等级、虚构性质及其他字段均只读，服务拒绝请求中任何额外字段。绝不改变航迹时间原点、原始报告/证据、已生成报告快照，不做分类判定或事实认证。未填资料保持未填，不生成真实事故内容。虚构标记不可通过本接口关闭。

## HTTP
- GET `/api/v1/cases/{case_id}/metadata` → 200 `{case,revision,lastChange}`。
- PATCH 同路径：`{operationId,expectedRevision,changes,sourceLabel,changeReason}` → 新快照。
- revision 是完整当前案件内容与最后一次 case.metadata.update 审计行的 SHA256 不透明版本值。与同事务写锁结合避免并发覆盖，并区分 A→B→A 的中间修改。旧版本返回409 `CASE_METADATA_CONFLICT`，不自动合并或重试。
- changes 至少一项且实际改变一项；title 非空、不可清除；其余四项非空文字或 null（显式移除键）。无变更422。所有来源/理由必填，作为调查人员声明，非系统核实结论。
- lastChange 为 null 或 `{operationId,utc,operator,sourceLabel,changeReason,fields}`，显示最近修改的出处与理由；导入的旧审计若无可解析结构，lastChange 为null而不是伪造。
- 更新和审计同事务。审计 before/after 为摘要，完整来源、理由及变更字段前后值保存在审计行 reason 扩展中的 JSON 字符串，避免长文本被400字符摘要截断。existing audit/包格式不变。
- 可读角色须 ais_sim 为 ReadOnly/ReadWrite；Redacted 没有档案脱敏规则，拒绝原文；Deny拒绝。PATCH另限 LeadInvestigator/Investigator 且 ais_sim ReadWrite。只沿用本地演示身份，非生产认证。
- 现有 GET cases/create/API合同不变；独立 case_metadata router不修改 cases/router。五字段已在既有 .mcase case.json/case.ext.json 中，不扩充包格式，须验证导出/新库导入及审计前后值。

## 并发依据
[RFC9110 §13](https://www.rfc-editor.org/rfc/rfc9110.html#name-conditional-requests) 说明前置条件可避免并行编辑互相覆盖。此处使用明确约定的业务 expectedRevision，而非宣称实现 HTTP If-Match/ETag 或完整 RFC 条件请求协议。

## UI 与验证
读取明确案件ID与数据性质；只编辑五文字字段，显示其余关键信息只读。保存前输入来源与理由。切案/身份/导航立即废弃旧响应；取消不保存。重复点击只发一次；409保留本地草稿但必须重新读取比较，绝不强推覆盖。网络/5xx/异常响应视为结果未知，只读核查后再由人决定，不盲重试。显示已生成报告不会自动更新/复核。

使用纯虚构测试数据验证角色/案件策略、跨案、全部只读字段拒绝、版本并发与ABA、长案号、无变化、空值和原文、审计失败回滚、进程重开、案件包往返、证据/船舶/环境/航迹不变、三尺寸、迟到响应与Back/Forward。不部署、不自动修改真实案件。

### 保存结果核查
operationId 是客户端生成的本次修改唯一标识，同案重复使用返回409、不写入。保留在完整审计reason与lastChange中；丢回复后，只有只读核查发现同operationId且修改值一致才可确认本次成功。若已发生后续修改或标识不同，即使文字相同也不得冒称本次提交成功，需明确提示未能确认并由人重新读取比较。

### 既有案件包标准化边界（D01裁定）
本片不改 .mcase 序列化。运行库中的 null 清除会移除可选键；跨包时原有 case.json 会将缺失 leadInvestigator/agencyName/summaryNotes 写为空字符串，均代表“未填写”，并非填入资料。placeName 在 case.ext.json 中仍按实际存在性保存。非空编辑文字及完整来源/理由/前后值审计必须原文保留。
revision 是当前案件表示和编辑审计的并发标识，不保证在跨库导入及包规范化后相同。规范化发生后客户端必须重新读取版本；旧token不得强行写入。原包还有其他既有序列化行为，本片不宣称整个CaseJSON字节级往返一致，亦不修改时间、坐标或等级。UI统一将缺键/空字符串显示“未填写”。
