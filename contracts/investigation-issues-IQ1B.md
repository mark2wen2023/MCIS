# IQ-1B read-only review snapshot
Base PR47 commit 11c6b41fad9ff4d308c5fddc4e25490299286fb4. Additive GET `/api/v1/cases/{caseId}/investigation-issues/{issueId}/review`.

Same conservative full-content authorization and current/historical source availability checks as IQ-1A. The existing authorization helper uses SQLite BEGIN IMMEDIATE before policy/source/state reads, retaining its reserved-writer boundary through response construction. It does not protect later delivery, distributed stores, or database tampering. Cache-Control no-store, ETag decimal issue revision. No write, external model, network call, state promotion, report, export or archive integration.

Response: `{issue,rows,interpretation:"manual-records-not-fact-determination"}`. `issue` is the existing detail view including `sourcesStale`, `archiveSupported:false`, `identityMode:"unverified-self-reported"`. Each row is `{hypothesis, verificationRecorded:boolean, verificationEvent:null|event}`. The full current RecordVerification event includes recorded activity/result/outcome/sourceRefs and self-reported actor/role. Null means no current-round/current-version record, not evidence of failure or fact status. Each stored outcome is a manual record, not a system judgment.

Projection verifies event type, round, hypothesis id/version, outcome and normalized source refs. Missing or inconsistent current event linkage returns 409 `ISSUE_HISTORY_INCONSISTENT`, not partial rows. Text is JSON data, not trusted HTML; clients must render it as text. Old overwritten verification events remain on the existing event-history endpoint, not falsely presented as current. Existing discussion packet remains in issue detail and is not regenerated by this endpoint. Existing 403/404/422 behavior retained. API does not change unsupported .mcase restriction.

Requires independent local API regression; browser, trusted identity, full production deployment and model ability are outside this increment.
