# W10.2 明确语义 UTC CSV 首次航迹输入（限定切片）

## 依据与边界
- 原型 `prototype/index.html` 的航迹页（论文4.5.3/5.3(3)）及 ARCHITECTURE §4.2：导入→时间标定→有效性→保留原件/来源/剔除原因→派生航迹；R-03 原件不可覆写。W10.1 的真实读取作为保存后回读入口。
- C# `Domain/Ais` 已有 NMEA1/2/3/5/18/19/24、多片段、CSV列映射/单位和时间解析；`Domain/Tracks` 有清洗/插值。不能把本轮 Web 的严格交换 CSV 解析称为这些能力的完整接通，也不另造清洗/插值权威实现。
- 对照 USCG NAVCEN Class A / Class B reports：1/2/3/18/19 原始SOG码1022是≥102.2节、1023不可用；COG原码3600不可用；秒字段60–63分别有状态含义。27号报文编码、分辨率和时间来源不同，不能套用。来源：https://www.navcen.uscg.gov/ais-class-a-reports ，https://www.navcen.uscg.gov/ais-class-b-reports 。本次直接访问403，依据工具返回的官方索引正文核对，不能声称实机原报文解析验收。
- 普通 CSV 的102.2节不能证明原码1022。因此本合同必须显式传入字段状态，不根据数值/文件名/来源名称猜报文协议。`reported`仅表示输入声明为数值，不表示精确测量、实测或已认证。不能自动补零、推断来源、回填COG作为HDG。

## 支持的输入
单案已登记单船、原先没有任何已存航迹。MCIS-UTC CSV v1，UTF-8（允许BOM），逗号分隔，固定列；非通用AIS/CSV自动识别。

必需列：`utc,latDeg,lonDeg,sogKn,sogStatus,cogDeg,cogStatus`。
可选配对列：`hdgDeg,hdgStatus`。
- `utc` 必须含完整日期、时分秒与Z，最多毫秒；基于案件 `caseEpochUtc` 计算相对秒。保留原UTC文本；不猜日期/时区、不做钟差修正、不承诺接收时间等于定位生成时间。
- `latDeg/lonDeg`：十进制度；`sogKn`：节；COG/HDG：真北顺时针度。经纬越界只判几何越界，不推断AIS原码。
- SOG状态：`reported/unavailable/lowerBound/unknown`。COG/HDG：`reported/unavailable/unknown`。有值不等于可计算；所有原值、状态留在原CSV。
- reported SOG 为非负有限值（包括0和102.2），reported COG/HDG 为[0,360)。SOG lowerBound不能当等号，保留诊断并阻断保存。必须字段 unavailable/unknown 同样阻断。
- HDG列整体省略，或明确unavailable时，派生点HDG为null。不可用原值如511只存于原件及诊断，不映射成有效艏向。HDG unknown 不猜测其含义。
- 必须用户提供资料来源说明及UTC时间依据说明。这些是人的声明，不能冒充现场提取人/原始提取时刻或真实性核验。
- 原记录严格时间递增，无重复。乱序/重复/任何阻断行全批拒绝保存，不静默排序、删点或部分保存。预览仍报告问题；原文件未保存前仍由用户持有。
- 文件/行/请求体有服务端限额，属于工程预算，不是海事质量标准。

## 操作与持久化
1. 用户选船、选文件、填写来源和时间依据。选择文件本身不上传，点“服务端预览”才发送。预览不写点、不登记证据、不写审计。
2. 预览展示目标案/船、纪元、SHA-256、点数、时间范围、诊断，最多展示前100个可解析点与前200项诊断，明确总数和截断；保存后已存点全部可分页核对。修改任一输入使预览和确认失效。
3. 用户明确确认本次文件/声明/目标后保存；服务器重算解析与预览摘要，绑定原bytes、元数据、版本、案件纪元。禁止信任客户端发回的点列表。
4. 保存只允许调查组与现有案件写权限；已存航迹船舶拒绝覆盖或追加。并发首次保存只有一个成功，相同原请求重试是同一结果，不重复点/保管链/审计。
5. 原CSV和导入诊断/元数据作为不可覆写文件，证据登记、保管链、航迹点与审计在同一个数据库事务。服务器生成路径/ID，不接受客户端路径。
6. 普通异常时数据库回滚并清理本请求新建文件。文件系统与SQLite并非跨存储崩溃ACID：进程在提交前崩溃可能留无引用孤儿文件，不得称全部崩溃情景原子。这不允许引用未完整写入的原件或覆盖既有原件。
7. 保存响应丢失时不能假报失败/成功，显示“结果未确认”，只读核查同摘要结果；再次提交只能沿用同一已确认请求幂等重试。关闭/切案不会撤销已发写请求。
8. 回读 GET tracks 进入W10.1检查；原件及诊断可回读/下载核SHA。现有 .mcase 机制以EvidenceRow索引带出原件和诊断，必须验收导出/再导入保留字节、点和审计。

## 不在本轮
NMEA/27号、自动列映射/单位识别、CSV无时区时间解释、AIS位级解码、清洗/删点/恢复、手绘、Hermite/ENU/天线修正、覆盖旧航迹、多文件合并、Unity启动、真实数据导入、正式身份认证、部署。reported与CSV来源声明不构成证据完整性或事实真实性保证。

## 独立验收要求
真实HTTP及真浏览器闭环；原bytes/BOM/换行/状态保留；102.2 reported 与lowerBound明确区分；无日期/坏日期/时区/乱序/重复/错案/错误单位及限额边界；无预览写入；权限和保密；数据库/文件失败回滚；重复/竞态；响应丢失核查；选文件/修改/关闭/切案/身份/Back迟到隔离；重开页面回读；案件包往返；1440/1920桌面及键盘。测试仅隔离合成夹具，不修改真实用户资料。

## D01 恢复核查完整性裁定
独立故障注入表明：历史回执与原件完好，不足以证明当前持久化航迹仍完整。恢复查询及同摘要重试必须按保存的配置/操作者/纪元重算绑定摘要及预期点，核对当前该船全部点的数量、数值和逐行来源。缺失、额外、数值/来源变更或当前纪元变化都失败关闭，不自动补点或覆写。此核查面向本轮“首次保存且不支持后续编辑”的合同；未来编辑须另定版本/原始与派生数据协议，不能悄悄改成宽松历史回执查询。
