## HTTP and input
Prefix /api/v1/cases/{case_id}/ecfc, endpoints GET /context, GET /draft, POST /preview, POST /save, GET /audit. All responses no-store. Preview is zero-write and returns profile, caseId, draft and validation. Save exact body {requestId:UUID,expectedDigest:sha256|null,acknowledgeArchiveLimitation:true,draft,expectedSources:[{evidenceId,title,sha256}]}; preview exact body {draft,expectedSources}. Strict UTF8 JSON, no duplicate/unknown keys, nonfinite numbers or invalid Unicode; 128 KiB/16 nesting; sources at most 8 unique registered IDs. Draft {scope,nodes,edges}; scope trimmed 1..1000 characters; nodes 0..40 of {id,kind:Event|Condition,text,timeSeconds:number|null,lane:integer,isPrimaryIncident:boolean,evidenceIds:string[]}; text trimmed 1..1000, ASCII ID ^[A-Za-z][A-Za-z0-9_-]{0,63}$, time absolute <=315576000 seconds relative to case epoch (not necessarily a known absolute UTC), lane -5..5. Each node's evidence IDs must be within expectedSources, no duplicates. Edges 0..80 of {id,from,to}. No client-supplied status, isPresumptive, edge kind or validation result.

Context {profile:MCIS-ECFC-DRAFT-1,caseId,sources,writeAllowed,identityMode:local-role-header,sourceBinding:registered-metadata-only,archiveSupported:false}. Sources bind registered same-case title/hash, not source bytes or factual truth. Metadata changes require explicit refresh/reselection; deleted/inaccessible sources deny stored draft/audit retrieval. Draft response {profile,caseId,document:null|Document,sourceStatus:none|unchanged|changed,persisted,identityMode}. Document {caseId,revision,digest,draft,sources,validation,status:Draft,strength:ToBeVerified,origin:Investigator,savedBy,savedRole,savedUtc}. Digest is opaque server SHA256 of recursive-sort compact UTF8 JSON {caseId,revision,draft,sources,validation}; do not rebuild it with JavaScript numeric serialization. Client verifies all response shapes, case/identity/request binding, and echoes, not authenticity. Core validation protocol is separately specified in ecfc-core-v1.md.

## Permission, transaction and audit
Unstructured graph text can contain any case content. Conservatively require Investigator/LeadInvestigator and ALL twelve existing policy categories ReadOnly/ReadWrite, no applicable field redaction rules. Save/preview additionally agent_drafts ReadWrite. Default Investigator is consequently refused; do not change headers/policies automatically to bypass. Context lists only valid same-case evidence rows after the same full gate. Audit needs the same full gate and source access for before/after documents. Local role/operator headers are self-reported, not authentication. Case document identity must match row key; operator is bounded nonblank Unicode text.

Phase 1 snapshots full case/policy/selected source records in a read transaction. Real CLI runs outside DB transaction. Phase 2 WRITE_LOCK and SQLite BEGIN IMMEDIATE rechecks snapshot, prior/current source access and optimistic expectedDigest, then atomically writes current graph + append-only full before/after audit + request receipt. Any failure before commit rolls back all three; a lost response after commit is UNKNOWN, not failure or success. Same UUID, exact canonical body, operator AND role returns original result after current source/permission checks. Different actor/body reuse409; conflicting expectedDigest409, never overwrite. Even old successful replay does not claim to be latest revision. No automatic POST retry. Audit returns newest50 summary events {revision,utc,operator,role,action:ecfc.draft.save,requestId,beforeDigest,afterDigest,prevHash,hash}; hashes provide local consistency, not identity/signature or independent evidence. No deletes. Unknown save metadata is scoped to case+operator+role; full pending body stays only in memory, not browser persistent storage. Prefer explicit identical retry while body is retained. Reload may lose request bytes but keeps the metadata lock. After explicitly re-reading latest draft and recent audit, an informed user may abandon LOCAL waiting (not cancel the server request), then must fresh-load the latest draft/digest before any new edit/save. Absence from latest50 audit is NOT proof of non-commit. CAS prevents silent stale overwrite, including an old operation completing later; no automatic new-ID retry. Late replies after navigation/identity switch or abandonment cannot alter the new session.
