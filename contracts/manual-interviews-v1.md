# W5.2b manual interview entry v1

Profile `MCIS-MANUAL-INTERVIEW-1`. Local self-reported role/operator, not authentication, signature or fact verification. Original document remains exclusively InterviewRow.doc; append-only receipts are separate and never store a duplicate original transcript. All paths use W5.2a original-content policy/source gates, no-store, and actual SQLite BEGIN IMMEDIATE before policy/document reads. GET is business-read-only but reserves the database writer while preparing its response.

## Routes
All under `/api/v1/cases/{case_id}/manual-interviews`.
- POST base: creates an unsigned EMPTY record, server assigned IR-number. Body required: `requestId` canonical lowercase UUID, `backupAcknowledged:true`, `interviewee` exact `{intervieweeId,name,role,affiliation}`, `startUtc`. Optional: `location`, `recorder`, `interviewers`, `sourceEvidenceId` (null or evidence ID). No other fields. Identity string fields nonblank <=200 Unicode codepoints; location/recorder <=500; interviewers <=16 nonblank strings <=200. startUtc mandatory UTC second precision YYYY-MM-DDTHH:mm:ssZ years1900..2100. Unknown time rejected, never replaced by current time. Optional text defaults empty, interviewers defaults [], source defaults null. Raw accepted strings are preserved.
- POST `/{record_id}/turns`: required `requestId`, `backupAcknowledged:true`, `expectedDigest` lowercase SHA256, `question`, `answer`; optional `utc` (same UTC format or null), `sensitiveFragments` (default []). Nonblank question/answer each <=16000 Unicode codepoints, saved exactly without trimming; max256 rounds total. <=64 nonblank sensitive fragments, each <=16000 and a literal substring of this question or answer. No old turns are edited; no automatic statement/crosscheck/signature.
- GET `/{record_id}`: `{profile,caseId,record,documentDigest,sourceBinding,signed,identityMode:'local-role-header'}`. record is the current stored original document, not historical request response; digest uses complete canonical JSON (sorted object keys, compact UTF8, finite numbers, array/string order/content unchanged). sourceBinding is `none`, `registered-metadata-only`, or `legacy-unverified` for a nonempty legacy hash without an evidenceId. Such a legacy hash is not verified provenance and blocks new append.
- GET `/requests/{request_id}`: original actor (exact self-reported role AND operator) only, plus CURRENT content and source permission. Returns the same metadata envelope below; not a guarantee that an absent/unavailable request never committed. A 404 must not trigger automatic new-ID submission.

POST response (201 on first success, 200 on same-request replay) and recovery GET (200):
`{profile,caseId,receipt,replayed,sourceBinding,currentDigest,identityMode:'local-role-header'}`.
`receipt` exact `{requestId,operation:'create'|'append-turn',recordId,beforeDigest:null|sha256,afterDigest:sha256,turnRound:null|integer,appliedUtc}`.
The receipt is immutable metadata describing the original successful operation; afterDigest/round are NOT necessarily current. `currentDigest` comes from the currently accessible record. Recovery uses replayed=true. No old original text is returned through a receipt. Client should GET current record, never apply a stale receipt as current document.

## Persistence / concurrency
Append-only InterviewRequestReceiptRow, key(case_id,request_id), stores request_digest, operation, record_id, actor role/operator and receipt JSON. Hash canonical supplied request plus case, operation, route record ID and actor. Missing optional fields versus supplied defaults are different requests; object key order is not. No raw request copy persisted.
Inside one transaction: current write gate; check matching request first; identical request+actor replays after current document/source READ check; changed request/actor409; only new append checks expectedDigest and signed status; save document + audit + receipt atomically. Repeated old expectedDigest succeeds only as exact previously successful replay. A readonly current actor may recover via GET but cannot POST replay through a now-nonwritable route. All old writers remain serialized by W5.2a and automatically invalidate current full-document digests. No separate revision counter or metadata sync hook.

Existing unsigned legacy records may be appended without enrollment if structurally valid, rounds sequential1..N, and source checks pass. Nonempty sourceSha256 without evidenceId rejects NEW append409; no clearing/guessing/rebinding. Signed records reject new append409. Exact successful replay can still report an earlier operation after a later signature, without editing it. If the current record disappeared, receipt recovery returns409, not a fabricated current state.

## Sources / backup
Optional source must be same-case registered and currently visible; sourceSha256 comes only from server metadata. Binding does not prove transcription fidelity or raw-byte revalidation. Current source/hash conflicts are checked on reads, writes and replay/recovery.
`backupAcknowledged:true` is only acknowledgment of a software limitation, NOT a legal signature or authenticated consent. Any receipt in a case, even after the record is deleted, blocks old `.mcase` export409 `INTERVIEW_RECEIPTS_BACKUP_UNSUPPORTED` before files/render/export audit. Never silently discard receipts. Full archive support is a later separately validated extension; W5.2a transcript import rejection remains.

## Strict inputs / errors
JSON only415; body max128KiB413 (check before extending buffer); duplicate keys, unknown fields, nonfinite numbers, invalid UTF8/unpaired surrogates, nesting>32, bad identifiers/times/types422 `MANUAL_INTERVIEW_INVALID`. Body fields and IDs never enter error text. Request actor mismatch/reusedID409 `INTERVIEW_REQUEST_CONFLICT`; digest conflict409 `INTERVIEW_VERSION_CONFLICT`; signed409 `INTERVIEW_SIGNED`; unsupported legacy state409 `INTERVIEW_STATE_UNSUPPORTED`; missing request404 `INTERVIEW_REQUEST_NOT_FOUND` (not proof of no commit); missing current receipt target409 `INTERVIEW_RECEIPT_TARGET_UNAVAILABLE`. W5.2a source/permission errors retain403/409; malformed legacy document409. No denied request writes audit, receipt, document or file. Unknown record GET404 only after permission gate.

Tests synthetic seed=False only: exact text/UTF16 safety, create/append/reopen/recover, repeat/conflicting IDs, actor isolation, concurrent same-version append one201+one409, legacy write invalidates digest, source changes, signed/orphan legacy, rollback including receipt, no-store, absent request uncertainty, backup denial even orphan receipt. Stub/LLM/core not involved.

Identifiers: route record_id matches `IR-[0-9]{2,}` with total length<=64. sourceEvidenceId matches ASCII `[A-Za-z0-9_-]{1,64}`. intervieweeId is an entered nonblank string<=200 codepoints, not an authenticated/government identifier. UTC second precision and years1900..2100 are engineering limits, not investigation standards; subsecond inputs are rejected, never silently rounded. Legacy GET preserves structurally valid original documents, including preexisting question/answer lengths beyond the new-entry limits; new append limits only the new turn, while enforcing total256 and existing sequential round numbering. Legacy invalid Unicode/nonfinite state rejects409 rather than normalizing it.

Digest is a SERVER opaque concurrency token, not a cross-language JCS format. Browser must preserve and return it, bound to the response case/record/actor and its request generation; do not recompute via JSON.stringify (legacy numeric representations may differ). Server recomputes and compares the complete stored document. Receipt metadata never substitutes for a fresh current-record read.

Backup scope distinction: this new receipt-triggered export409 is stricter than legacy behavior. Older case packages are NOT complete system backups: report documents/operation snapshots are not guaranteed to restore, and a legacy package containing testimony can pass integrity verification yet be rejected by the W5.2a import boundary. This slice does not fix those older gaps or advertise full restore. Full report+interview+receipt archival is a separate future contract. Integrity verification is not a promise of supported restoration.

Implementation boundary: JSON is read asynchronously with its byte bound; synchronous transactional helpers create/use/close their own sessions in a worker thread, so waiting for SQLite writer acquisition does not block the ASGI event loop. All current/recovery/write paths require an existing CaseRow after authorization; orphan documents are not treated as a usable case. Missing case404 precedes missing receipt-target409. New source binding also requires the stored evidence document's caseId/evidenceId to match its row and a canonical64-lowercase-hex SHA; malformed registration409 INTERVIEW_SOURCE_INVALID, without reading original files or changing W5.2a legacy semantics.

Record identity reservation: current rows AND all receipt-referenced record IDs reserve numbers permanently within the case. New manual allocation and automatic legacy allocation skip reserved IDs. Legacy create explicitly requesting an ID whose document is missing but whose receipt survives returns409 INTERVIEW_RECORD_ID_RESERVED. It cannot rebind an old receipt to a different newly created record. No deletion API or generation-reset mechanism is introduced.

Concurrency correction: successful shared `BEGIN IMMEDIATE` records a private proof bound to the root SessionTransaction, connection and creating thread. Audit sequence allocation skips the Python WRITE_LOCK only while that same SQLite writer transaction remains active, on that thread (including savepoints within that proven root writer). SQLite serializes this proven path through commit. This avoids the confirmed inverse wait against existing outer WRITE_LOCK → BEGIN callers. Ordinary/deferred transactions, stale proofs, unproven nested transactions and other dialects retain the old lock. Session sharing across threads and raw driver COMMIT/ROLLBACK bypassing SQLAlchemy are unsupported. This is not a claim that all legacy routes support multi-process writers; two-process testing covers only the explicitly reserved path. Savepoint rollback/release retains the reserved outer writer; full root commit/rollback invalidates the proof.
