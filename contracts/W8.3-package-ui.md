# W8.3 案件包预检与导出（限定切片）

## 设计与专业依据
- 原型 `prototype/index.html` #lobby 的打开 .mcase、#analysis 的导出 .mcase；沿用案件大厅卡片、深色面板、明确案件标题。导出在对应案件卡片上，避免误导出当前演示案。
- `ARCHITECTURE.md` §11 与 R-03：原始证据保持原样，manifest SHA-256 逐文件复核，缺失/篡改应显著提示。SHA-256 一致性不等于来源真实性、事故事实或责任认定。
- `contracts/CONTRACTS.md` §4.1：缺失/篡改无效，额外文件仅报告；§8 已知导入文件不回滚，因此本轮不开放导入。
- 复用已有 GET cases/{caseId}/export、POST packages:verify；不改接口、权限、服务或 .mcase 格式。

## 范围与验收
1. 调查组（LeadInvestigator / Investigator）可选本地 .mcase 后主动上传本机服务预检，显示文件名、大小、manifest案件ID、缺失/篡改/额外文件；只说清单哈希检查通过，不说可安全导入。
2. 文件选择本身不上传；每次检查均对当前选择发一次原始ZIP请求。选择变化、关闭、身份/页面变化销毁结果且中止请求，迟到结果不得串入新状态。
3. 当前身份允许时各案件卡片导出其编码caseId，收到ZIP才生成本地下载；错误不得下载为包；防重复点击、身份/离开取消、对象URL释放。浏览器保存结果无法确认，只显示已交给浏览器下载。
4. 非调查组不展示文件上传/完整包导出控制；服务仍是最终权限边界。无生产认证，角色头不可当安全认证。
5. 100 MiB 上传UI限制仅为交互保护，不是ZIP解压资源预算。文件仅限可信来源；预检不验证JSON语义、审计链、真实性、不写入案件库、不证明导入成功。
6. 验证 malformed 响应、403/422/500、空文件、重复点击、选择/身份切换/取消/Back、特殊caseId、已存在案件、非虚构标签、额外文件与不一致isValid。
