# Internal exact audio file-range read / 1

Opt-in function in reports/audio_reference_range.py; not a route or default report output. Base media reader: 3a19c75221dc770042708972bf7a1a36d681e121. Original media_reference.py and media_reference_reader.py remain byte-for-byte unchanged, including exact-media-report-reference/1 digest recipe.

Inputs: existing trusted case-scoped reader, exact case_id/evidence_id/run_id/revision/segment_id, and mandatory expected_reference_sha256 from a trusted persisted report reference. Client-provided identities/digest are not authorization. Caller must establish report/media authorization intersection, source/task validity checks and one consistent read transaction before invoking. No existing report call site is asserted to meet those prerequisites.

The wrapper captures the exact rows already consumed by read_exact_media_reference (revision zero, selected revision, exact evidence), using deep copies. It does not reread, fetch latest, scan history, open media, start a transaction or manufacture a snapshot. Capturing Python rows cannot make inconsistent upstream reads consistent. Reuse ScopedMediaReader and the same caller-owned transaction; do not install in reports/sources.py or expose to frontend before those guarantees are independently established.

Basis provenance: audio_review/app.py source() reads bounded complete PCM WAV, checks actual bytes against receipt/registered current SHA and derives frames/rate; attach() persists that audio basis with validated matching machineDraft. V3 source includes frameCount/sampleRateHz; v2 requires integral millisecond duration. These are stored historical declarations whose provenance must remain trusted; this function does not reread WAV bytes or verify audit/storage integrity. Old reference digest includes human startMs/endMs/timeStatus but does not independently bind every initial audio metadata field. Therefore the trusted initial row and source checks are prerequisites, not a conclusion of matching the reference digest. Do not use arbitrary dicts or restored unverified rows in a product call.

Validation: require original PCM format, supported channel/sample width, integer 8000..48000Hz, integer frames representing 1..60 seconds; source duration must equal ceiling of frames*1000/rate. V3 explicit rate/frame count must match; v2 requires exact integral duration. Missing/unsupported/inconsistent historical basis is unavailable, never inferred from durationMs alone. Declared range uses integer 0 <= startMs < endMs and endMs*rate <= frames*1000. No rounding to make invalid endpoints valid.

Both null endpoints plus timeStatus=unknown return explicit unknown with null endpoints. Only operator_declared with valid bounds returns a range. Missing, partial or inconsistent endpoints are unavailable rather than fabricated. hearingStatus never supplies a time or proves fact verification. Segment must equal the selected exact revision's target after reference verification.

Output exact-audio-file-range/1 contains case/evidence/run/revision/segment, verified referenceSha256, declared sourceSha256, rangeStatus/startMs/endMs, original sample timeBasis (file-relative milliseconds), factVerified=false and mediaRetrieved=false. No file path, bytes, URL, permission, token or automatic playback. These milliseconds are not incident clock time. This result is separate from the old report projection: existing calls/output/digests unchanged.
