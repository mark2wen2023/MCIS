# W20.3 智能体协作状态（只读，不是主会话或任务编排）

基线main80fad29。原ARCHITECTURE §15.5定义六专业角色与人工确认的草稿；现有GET /agents仅返回配置登记，只有people_ops可配置本机模型。系统没有主智能体会话、调度任务、实时执行进度或运行心跳API。本片不新增这些能力，不伪造聊天、任务状态、进度或已完成工作。

专业依据沿用W20.2已核查的IMO MSC.255(84) §22.2/23（调查资料访问与披露）、NIST AI600-1 MS-2.5-003/MS-2.5-001（核查来源，不从有限测试推断能力）及WCAG2.2状态反馈设计原则。具体落实：后端权限最终裁决；页面只展示真实读取状态，不把configured说成模型可用，不把草稿审核说成任务执行成功，不宣称法规/无障碍全面合规。

## 页面与现有接口
`#/agents?case=<id>`为只读协作状态页，保留案件上下文。未授权角色不发起登记或队列请求、不展示模型信息；调查组及AgentService可尝试读取，实际队列仍由后端案件策略决定。无写按钮、无推理触发、无模型配置更改、无后台轮询。

- 六角色登记来自GET /agents；configured显示“已配置 · 连接与能力未验证”，not_connected显示“未连接”，配置错误单独显示。登记成功不代表运行中，读取失败不替换为“未连接”。显示最近成功读取时间（客户端本次读取时间，不是服务心跳）。
- 案件草稿列表来自GET /cases/{caseId}/agents/drafts；仅展示严格校验后的元信息（ID、角色、类别、审核状态、引用条数、模型标识、记录时间），不渲染payload、原文、审核者或审核理由。请求携带真实当前声明身份，cache:no-store，取消旧请求且丢弃跨案件/身份/导航响应。无权限403明确拒绝，不伪装空列表；列表中的任何跨案、重复或非法元信息导致整批拒绝展示。
- 所有审核状态计数只针对本次实际读取列表。PendingReview是草稿待审，不是任务排队；Confirmed/Modified仅表示人工审核登记，写回效果以原模块记录为准。不展示任务成功率/进度百分比或据模型名认定模型真的参与。
- 仅people_ops + statement_extraction + interviewStatements且targetEntityId与payload.recordId一致的记录可链接到既有笔录页，保留case/record；导航不发推理/审核请求。其余类型说明本页仅登记，无专用审核入口。不会误将旧schema兼容草稿变成可执行任务。
- 手动刷新先清旧数据；两个数据源分别有加载/失败/空状态。草稿按待审/全部/已处理筛选并客户端分页20条（底层现有API本身无服务端分页；不宣称支持无限规模）。不存浏览器持久缓存。主会话与自动调度明确标为未接通，不提供假发送框。

## 验收范围
仅临时合成案件与响应数据；覆盖权限、空/失败/格式、跨案/身份、迟到响应、重复刷新、分页/链接编码、HTML转义和移动端。现有真实API临时数据库读路径验收，不调用真实模型或加载真实资料；不改后端合同，不触W11、不部署。
