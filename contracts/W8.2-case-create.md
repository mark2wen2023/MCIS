# W8.2 案件新建闭环

## 范围与产品结果

从案件大厅新建一个空案件并进入其证据中心，不必修改种子或调用 API。复用既有 POST /api/v1/cases、GET /cases/{caseId} 与 case.schema.json，不新增服务路由，不修改公开报告、种子、计算核心、生产认证或部署。编辑、删除及 .mcase 导入导出不属于本片。

## 表单与协议

- LeadInvestigator、Investigator 可使用；其它身份不显示可提交表单，服务器权限仍为最终裁定。当前角色来自本地演示身份，不称为生产认证。
- 必填案号（3 字符以上、ASCII 字母数字 . _ -）、非空标题、事故类型、事故 UTC 时间、经纬度、虚构/非虚构标记；地点可选。纬度 [-90,90]、经度 [-180,180]，必须为有限数且空字符串不视为 0。
- schemaVersion 为 1.0.0；新案 caseEpochUtc 等于明确输入的 incidentTimeUtc（在 UI 解释），displayTimeZoneOffsetMinutes 为 0（UTC），不伪造时长、船舶或航迹。事故时间不使用隐含本地时区。
- POST 只显式提交一次；按钮防双击。成功后提供明确成功状态及进入案件入口，列表重新加载。所有用户文本以 React 文本渲染。

## 错误与中断

- 403 不重试写入；409 明确案号已存在，不覆盖现有数据。422 保留输入以便修正。
- 网络断开/5xx/无效成功响应可能已经写入，不自动重发。锁定该次载荷，允许只读核查同一 caseId：若返回值所有提交字段相等，确认已创建；若不同，提示冲突；404 可让用户明确再次提交，读取失败继续不确定状态。
- 取消/关闭/身份改变/离开页面不得让迟到响应跳转或污染新的身份/新表单。身份改变清除本次表单与旧状态。取消不是取消服务端已发出的写入，提交中不能误报已取消。
- 页面 Back/Forward、重复打开、连续提交、重读失败与恢复需验收。输入错误不调用 POST。

## 验收

实现自测、TypeScript、生产构建、既有前端回归；独立验证真实本地 HTTP 创建→列表→进入→元数据一致及恰好一条 case.create 审计、未授权角色拒绝、重复案号不覆盖；浏览器覆盖正常流程、校验、双击、403/409/422、丢响应后只读恢复、身份/导航中断、1440 与 768 布局。冻结后独立验收不得修改实现。不得把 mock 浏览器说成真实 HTTP。

## 新建案件进入证据中心的显示验收

- Layout 与证据中心均使用实际案件标题及保守虚构/非虚构标识。没有来源依据时不得称为“公开报告”，也不得借用 Lily/Mary 名称。
- 证据登记时间、保管链时间、冲突时间、图表轴及 tooltip 与时区标签一致，按案件 displayTimeZoneOffsetMinutes 显示。验收至少覆盖 UTC、UTC+08:00、负偏移及跨日。仅显示转换，不改变已存 UTC 或计算数据；采用 Evidence 专用 helper，共享 format.ts 不变。
- 已加载且证据数组为空时明确显示暂无证据，不得永久标为加载中；无事件/CPA 的新案不绘制图表或伪造船名、时长、540 秒碰撞标记。
- Lily/Mary 专用船名、演示时长与碰撞线只能用于规范 CASE_ID 演示案；其它案件即使标为虚构也不借用这些事实。
