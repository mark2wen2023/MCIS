# W10 restored-track receipt isolation v1 / working-record archive v2

## 1. Defect and boundary

A synthetic real-HTTP reproduction on main d44bb4e demonstrated that restoring a1.2 case with W10 CSV/report files caused the original digest GET, vessel receipt list and same-body commit to return200/replayed:true. The original files were preserved, but the original transaction was incorrectly presented as active in the destination. This slice fixes that receipt boundary, not AIS truth, clock accuracy, authentication, general distributed concurrency or complete project restoration.

Use only synthetic validation. Do not modify original CSV, report JSON, audit/custody lines, track points, professional core, W11 or existing historical review decisions. No deployment. Imported original actors are self-reported history, not current authorization. Unknown write status must never be cleared by an archive-only response.

## 9. Upgrade boundary: local-origin marker, not imported authority

Introduce append-only `track_local_receipts` with exact columns case_id, preview_digest (composite primary key), source_evidence_id, report_evidence_id, report_sha256. All strings use existing same-case ID/lowercase64hex rules. No password, token or cryptographic trust assertion is stored. This marker says only that **this upgraded database's instrumented commit path** completed that operation locally. It is not a verified personal identity and cannot prevent a database administrator forging state. SQLite UPDATE/DELETE triggers reject changes.

A newly accepted W10 commit inserts the marker in the same real SQL transaction as points, both evidence records, custody/audit and exclusive original-file writes. Failure rolls back marker with all other rows and cleans only newly created files under existing crash limitations. Marker must bind the exact registered source/report IDs and report bytes hash before any active replay. That original report hash covers its original operator/role, full metadata, source hash, receipt and preview; original actor/role must also equal deterministic digest reconstruction. They are not silently replaced by the current caller. No redundant actor column is inferred as authentication. No importer, startup process, receipt GET, preview or download creates or backfills a marker. The original report/CSV remains the source record; marker is not a second receipt body.

Old receipt resolution becomes a three-way boundary, after appropriate current authorization:
0. Both archived index and local marker exist for this digest: integrity409, never select local marker to activate.
1. archived track-intake index alone exists:409 ARCHIVE_HISTORY_ONLY, never active.
2. no archive index and a valid matching local marker exists: existing active replay rules apply, including actual source/points reconstruction and same request digest checks.
3. neither exists:409 TRACK_ORIGIN_UNVERIFIED when original track-import artifacts are present; do not infer local origin from an old package receipt, timestamp, audit phrase, caller assertion, filename or presence/absence of source.mcase. If no original artifact and no marker/index exists, retain ordinary not-found/new-import behavior; a marker with missing original artifact is integrity409, not eligibility for reuse.

This deliberately affects BOTH previously restored databases AND genuinely local pre-upgrade W10 receipts: neither has the new marker, so their successful-active-replay claims become unavailable. It does not mean their original import failed, their data is corrupt, or that users should resubmit. Existing points, original CSV/report and original chains are untouched; ordinary authorized evidence access retains its existing behavior for unclassified originals. Specifically the existing case evidence directory and GET `/evidence/{evidenceId}/content` remain the explicit access path under their existing current permissions; no synthetic receipt is required. Old W10 receipt-dependent source/report downloads refuse ORIGIN_UNVERIFIED. This does not newly certify the older evidence endpoint as a full-content historical read boundary. Once a validated archive is restored with explicit historical indexes, the stronger new history-only access rules apply to both evidence items. They may be fully validated and exported as1.3 archive-only history without inventing a marker. No automatic old-data cleanup, fresh request ID, nonce, repeated commit, or migration occurs. New future inputs for empty vessels continue normally.

Every export validates all case local markers against original records; orphan markers, mismatched digest/IDs/hash, or simultaneous local and archived ownership for the same digest reject rather than disappear. Marker rows are an explicitly non-transferable runtime-origin mechanism, not portable business content; they are never serialized/restored as active authority. Complete original receipt content is carried by the track-intake index and original report bytes instead. Add only this exact case table to the working-archive supported-table set, with these validation rules; do not globally ignore unknown tables. Imported markers in a forged archive/unknown member reject. Both evidence IDs and digest remain reserved from local markers or archived indexes if original rows are lost.
