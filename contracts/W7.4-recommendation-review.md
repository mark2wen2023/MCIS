# W7.4 安全建议只读核查

Base: main a76cc56e13caa79b91e5b0036a838851fc967869 (W7ACCESS security repair merged first). Existing recommendation.schema.json and audit-event.schema.json remain authoritative; no API/schema change.

## Outcome and professional basis
Select existing board card → explicitly open full-content review → GET current recommendation body and recorded responses → optionally GET separately authorized audit summaries → close back to board. Read-only is not delivery, acceptance, implementation verification or legal compliance. Existing Issued is a local state, not evidence of external delivery.

IMO MSC.255(84), §1.1 prevention rather than blame/liability; §13.4/§25.3 consideration of comments; §13.5 checking accuracy/completeness supports exposing original text and recorded replies for human checking. §25.2 confidentiality supports separate server authorization. These are design references, not a claim that this UI completes required consultation or fixes all deadlines.
Source: https://wwwcdn.imo.org/localresources/en/KnowledgeCentre/IndexofIMOResolutions/MSCResolutions/MSC.255%2884%29.pdf

## API and permissions
- Conservative new UI entry limited to LeadInvestigator/Investigator; external/Agent roles make no new reader requests. Backend W7ACCESS now enforces conservative full-content access, including derived audit/export paths. Default Investigator and external roles are denied. A UI guard is not the security boundary, and local role headers are not production authentication.
- Only GET /api/v1/cases/{case}/recommendations/{id}; existing W7ACCESS require_content decides permissions. No board payload fallback after denial/error.
- Optional explicit GET .../{id}/history; existing audit and derived-content checks remain authoritative. Failure is separate, clears old audit and does not hide a successful recommendation response.
- History currently returns earliest up to 200 events, not a complete ledger. UI states this limit; it does not claim chain verification or fetch raw audit lines.
- Requests encode path identifiers, capture identity, use no-store and abort on refresh/close/context change. Identity includes role and operator. This development header mechanism is NOT production authentication.
- All asynchronous completion guarded by identity/navigation generation and case/id. Changing identity, navigation, selection, closing and refreshing removes old content. No persisted body/reply/audit cache, no background polling. Open reader is a point-in-time snapshot; manual refresh is required to obtain newer records.
- Strict response projection validates case/id, required rendered fields, enums/timestamps and all response entries. Audit validates every event's caseId, category=SafetyRec, entityType=recommendation, entityId, unique seq, and rendered field types. Bad batch fails closed; raw unexpected fields, raw line, snapshotRef are not rendered. Plain text only, no HTML or URL dereference.

## Non-goals
No PATCH/POST, editor, new recommendations, transitions, notifications, external sending, model or deployment. This does not repair existing W7 writers' concurrency/uncertain-outcome behavior. UpdateDraft stays deferred until atomic version checks, durable receipts and compatible transaction/audit lock ordering are designed and verified. Existing board/consultation operations outside this new reader are unchanged.

## Validation
Synthetic-only service permission/read/no-mutation checks, pure projection cases, browser interactions with delayed identity/navigation/selection, separate audit errors, malformed payloads and actual HTTP. Independent acceptance must verify frozen files and negative boundaries. No real incident/private data or external communications.
