# W7.5 draft body edit

GET `/api/v1/cases/{case_id}/recommendations/{rec_id}/body-edit` returns `{caseId,id,body,causeNodeIds,status,version,versions}` after existing original-content access checks. `version` is SHA256 of the complete stored recommendation plus the latest recommendation audit-line digest. It is a concurrency token, not identity or truth. `versions` contains the newest20 body-edit records, each `{seq,utc,before,after,causeNodeIds,baseVersion}`; full history remains in the protected append-only audit lines. Historical values are local records, not authenticated source evidence. Legacy pre-feature body edits have no reconstructed full history.

PUT same path accepts exactly `{expectedVersion:64 lowercase hex,body:string(max20000 Unicode codepoints)}`. SQLite reserved transaction checks current permissions, case, Draft state and exact token before saving. Same text/current token returns unchanged without audit. Stale tokens return409 including after a successful save with lost response; there is no write retry/receipt claim. The UI retains the proposed text on unknown outcome, disables writes, and asks the user to reread current state before deciding again. Concurrent writers with one token have one winner. Body text remains literal (empty allowed); invalid UTF-8/surrogates are rejected. Existing bodies over20000 cannot be edited in this slice.

Successful edits preserve all other recommendation fields including causeNodeIds, and append full old/new body and source-node association in an audit reason JSON v1 marked `draft_body_edit_not_fact_approval`. Before/after audit summaries remain bounded; full values are in reason. Audit failure rolls back body and history together. PUT response is the same view with new token. No fact/approval/status transition occurs. Generic PATCH with body explicitly set returns428 after access check, directing callers to versioned PUT; no unversioned body overwrite remains.

Responses use no-store. The existing local header-based role/operator mechanism is unchanged and is not production authentication. No new privilege grants, model calls, uploads, evidence mutation or schema/table changes. The current cause-node IDs are retained declarations; their semantic validity is not re-certified. An exact restored record+audit can retain its version token: this is document concurrency, not an incarnation/authenticity guarantee.
