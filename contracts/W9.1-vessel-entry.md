# W9.1 Vessel entry: bounded first slice

Base main: `0a29f28eeabae8087978de000caf47e5fe2aff30`. Implements the static-parameter subset of ROADMAP W9 / screen 03, not all W9.

## Contract

`POST /api/v1/cases/{caseId}/vessels` accepts a Vessel and returns the persisted Vessel, 201. Existing GET and old documents remain unchanged. New `parameterSources` is an optional additive map from populated parameter keys to `{sourceLabel, kind}`; kind is `Direct` / `Derived` / `Estimated` (【直接】/【推算】/【估计】). These are user declarations, not AI extraction or independent verification. Existing source-less records display “未登记来源（既有记录）”. No sample data is altered.

Only LeadInvestigator/Investigator with case `ais_sim=ReadWrite` may create. Existing read policy applies to listing. Local role headers are demo identity, not production authentication. The server validates case existence, exact body/path case identity, original Vessel schema, nonblank unpadded vesselId/name, and finite dimensions. loaM/beamM/displacementTons must be >0; drafts >=0. Optional absent values stay absent, never zero-filled. Each supplied source must name a present parameter and have nonblank sourceLabel. Non-fictional cases require a source for every supplied parameter except identity keys and UI color. No invented sources/default measurements.

Duplicate vesselId in the same case returns 409 VESSEL_EXISTS without replacement or new audit. The same ID in another case is allowed. Case mismatch returns 422 CASE_MISMATCH; invalid new input returns 422 CONTRACT_VIOLATION. Unknown case 404. Successful create and one `vessel.create` audit are atomic under the existing SQLite single-process write lock; failed writes leave neither. No update/delete endpoints.

## UI and acceptance

`#/ships?case=...` binds every read/write to the case, retaining case navigation. Shows real case title and fictional/non-fictional identity. Empty case has no invented vessels, dimensions, tracks, or computed results. Input includes identity and existing static schema fields with units and per-field provenance. Closing cancels the local draft only; saved records survive reload/reopen. Repeated submit is synchronously guarded. Identity/case switches discard stale responses and drafts. Read-only identities cannot submit; server remains authoritative for custom policies. Errors keep inputs. Ambiguous write failure permits only read-only verification before a manual retry. A conflicting existing ID never gets overwritten. Unknown case never falls back to demo data.
