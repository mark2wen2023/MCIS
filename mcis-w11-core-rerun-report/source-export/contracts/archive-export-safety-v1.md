# Archive export safety boundary A

Existing `.mcase` export is not a complete case backup. Report documents and report operation snapshots are not currently serialized; transcript restore is explicitly unsupported. Before assembling files or appending export audit, and after existing full-content/source permission checks, GET `/api/v1/cases/{case_id}/export` returns 409 `ARCHIVE_RESTORE_UNSUPPORTED` if the case contains any InterviewRow, ReportRow or ReportAuditRow (including orphan/GISIS snapshots), or report/interview-related residual audit recognized by the existing conservative event classifiers. Unclassifiable audit lines are conservatively blocked. Denied callers still receive 403 without learning archive state. Success/error responses retain no-store.

Manual interview receipts retain their earlier dedicated 409 `INTERVIEW_RECEIPTS_BACKUP_UNSUPPORTED`, including orphan receipts. No data is deleted, normalized or rewritten; refusal produces no package files or export audit. Existing source-policy denial/conflict may precede this unsupported-content response. Plain supported basic/HFACS export paths remain unchanged. This patch does not add restore support or imply all other business modules are safely recoverable. Integrity verification alone is not recoverability verification. A versioned full working-record extension requires separate design and acceptance.
