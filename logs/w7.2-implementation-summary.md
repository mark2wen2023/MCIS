# W7.2 local consultation lifecycle UI

Frozen for independent acceptance. New UI handles fixed-default30-day opening, recording an already-confirmed waiver, and requesting closure. Each mutation requires a local review/confirmation step. No attachments uploaded, no external messages delivered, no policy decisions made on behalf of parties.

New-round validation trims required version/party IDs/names, rejects duplicate case-sensitive IDs, normalizes optional SHA256 to64 lowercase hex, submits only days30/isAgreedDeadline=false. It never claims provided file hash is verified. Existing open rounds block creation; empty cases can create their first round.

Waiver offers only not-yet-replied/not-waived parties in an open round and requires trimmed reason. Closure warns no reopen exists and Pending comments remain decidable; local time is a hint only, not authorization. Server enforces allReplied-or-deadline.

Uses W7.1 case/identity session invalidation and synchronous write gate. Every failed mutation triggers read-only reconciliation, not resubmission. During reload policy/data are cleared; write access only restores after both policy and rounds successfully reload. Read failure keeps writes blocked. After successful creation selected round updates to returned roundNo.

Known limitations unchanged: server accepts some blank/duplicate party inputs via direct API, lacks cross-client open-round atomicity/idempotency, and its non30/default audit wording is inconsistent. UI restrictions do not fix server validation or guarantee distributed exactly-once. This slice intentionally offers only30days. No HTTP/contracts/backend changes.

Self-tests and full web/build results: logs/w7.2-web-selftest-regression.txt. New model/static-render checks are not browser interaction. Source lint exits0 with existing warnings outside this slice; build warns bundle size over1500kB. W7.1 frozen history unchanged. Pending independent HTTP and browser acceptance. No stage/push/image upload.

Pre-acceptance review correction: mutation catch now reloads parent audit as well as round/policy reads. A committed write whose HTTP response was lost can therefore reconcile both state and audit. This is read-only recovery, never a repeated mutation. Full suites/build rerun after correction.
