# W4 proposed inline alignment preview: read-only design review

Status: source-only review; no implementation, exploit, permission probe or new test executed. Proposed endpoint is NOT present or approved by current OpenAPI.

## Evidence and entry points
- service/mcis_service/timeline/router.py: timeline/conflicts GET load case then require resource `timeline`; writes require write=True. Timeline response gets caseEpochUtc from loaded case. add_event derives UTC from that epoch, not caller UTC.
- service/mcis_service/redaction/{policy,gateway}.py: default timeline LeadInvestigator/Investigator RW; ExternalExpert/InterestedState/AgentService RO; Public Deny. Actual per-case stored policy wins; unknown role/category defaults Deny. Read-only preview should use require(...,'timeline'), not require(write=True), and should not replace policy or grant new role rights.
- service/mcis_service/colreg/router.py core_align currently forwards arbitrary body without case load or require. It only validates returned conflicts. This route is not a safe preview boundary.
- tools/mcis-core/src/AlignCommand.cs Run/ReadLines/ReadManualAnchors: sources and manualAnchors accept text or path. ReadLines can read server absolute/relative paths. text priority does NOT make accepting a path key safe. caseId/epoch are supplied directly by request today. Result includes epoch, caseId, diagnostics, conflicts, calibration and stats.
- service/mcis_service/colreg/core_client.py invokes configured local command with stdin JSON and timeout, no shell; error messages may expose local command/path/stderr. Preview should not forward internal diagnostics blindly on infrastructure failures.
- contracts/openapi.yaml /core/align accepts generic object only. CONTRACTS.md still lists align NOT_IMPLEMENTED, while implementation exists. No dedicated inline preview request/response, size budget, authorization, persistence or error contract.

## Recommended safe boundary (requires contract registration before code)
A new case-scoped POST, e.g. /cases/{caseId}/timeline:preview-align, is feasible WITHOUT writing DB or merging conflicts. Path case selects authoritative stored case and epoch; body must not control caseId/caseEpochUtc. Reject these unknown fields rather than silently creating a misleading successful request. Only authorized local inline data is processed; no evidence-file lookup or automatic archived-track retrieval in this slice.

Define strict nested DTOs with extra=forbid and explicitly reconstruct every forwarded object. Never spread the raw body/model extras into core input. Minimal allowed fields: sources with sourceId, explicit supported format, text and only documented bounded parser options; optional referenceSourceId/offsetMethod/calibrate, inline manualAnchors.text, typed thresholds. If supporting csvMapping, whitelist its properties and each columns entry too; textValues is bounded string-to-finite-number mapping, not a generic object. No path key at any parser object (including null, alongside text, traversal, absolute, file URL or manualAnchors); no server path/output directory/config/command selectors. Plain source text may contain a path-looking literal as data: rejecting every slash in text is neither necessary nor correct. If mediaManifest allowed, confirm its importer never opens media targets; otherwise defer it in first slice.

Case/epoch must be injected ONLY from loaded case, then response caseId/epoch and each conflict caseId validated against that same scope (do not merely overwrite mismatched output). Return preview:true/persisted:false, explicit unregistered-input provenance, and no links implying registered evidence or persisted conflict IDs. Core-generated IDs can collide with archived conflicts; they remain preview-only. No put_doc/audit.append/runs.ensure/commit of changed rows, no stored clock correction, no conflict status/resolution update. Existing DB read session may commit a read-only transaction; assert semantic state/audit unchanged.

Set documented request bytes/source count/total text chars/line and mapping/anchor limits, reject nonfinite numbers and unsupported enum/type values, and retain a bounded core timeout. Numeric option ranges need domain-contract decisions, not invented frontend constants. Permission check must happen before core invocation or file access. RO allowed is appropriate only for inline computation with timeline output; it does NOT grant VDR audio, testimony or restricted evidence retrieval. If future feature imports server evidence, separate permissions/redaction/provenance checks are required.

## Independent acceptance requirements
- Default 6 roles + stored per-case policy overrides: RW/RO permitted as existing timeline read contract; Deny/unknown 403, core spy not called. Unknown case 404 and no invocation. Do not rely only on UI policy or claimed role labels.
- Two cases with deliberately different epochs: injected core payload/result matches URL case, unauthorized case cannot borrow allowed-case policy; caller case/epoch rejected, even apparently matching. UI selected case/identity change clears input/output/errors, cancels or ignores stale response; stale preview cannot be shown under new case title. Database epoch and frontend request generation are different concepts.
- Strict extra-field rejection at top/source/manualAnchors/csvMapping/column/threshold levels. Test path-only, text+path, null path, nested path, absolute/traversal/file URL paths; validation before core spawn. Assert reconstructed payload has only listed properties with spy. Do not test real secret-file reads.
- Valid NMEA and supported CSV/manual inline cases through real local core with known expected offsets/conflicts; malformed text/unsupported format/oversized input/nonfinite/malformed options fail clearly. Successful import may still have no anchors or failed calibration: report diagnostics, never claim calibration success just because HTTP is 200.
- Snapshot all affected case docs/conflicts/timeline/clock values and audit rows for both cases before/after success, domain error and core timeout; exact unchanged state. Test existing manual conflict statuses/resolutions remain intact.
- Core output wrong case/epoch/malformed conflicts fails closed; infrastructure failures show safe error, not stderr/server paths. Unknown outcome does not imply persisted write since endpoint has none.

## Unresolved scope/contract decisions
New route/request/response schema and error codes; format support and bounded parser options; byte/CPU budget; treatment of case metadata in request; response provenance/preview marker and mismatch validation; default-date interpretation (explicit date vs case epoch-derived fallback); error sanitization. Current bare /core/align remains a separate exposure even if UI stops using it: adding safe proxy alone cannot claim whole service path-read/permission vulnerability fixed. Disabling or tightening that old documented route is a separate compatibility/security decision and requires explicit scope. Existing header-based role mechanism is reused, not upgraded into production authentication by this slice.
