## 需求
1. 模板（service/mcis_service/reports/templates.py）：三套 templateId：`imo-cic`（IMO 事故调查规则 Casualty Investigation Code，MSC.255(84) 第 14 章报告要素）、`maib`（MAIB 报告结构：Synopsis / Factual information / Analysis / Conclusions / Action taken / Recommendations）、`cn-msa`（中国海事事故调查报告：概况/经过/原因分析/责任…注意：本系统“不作责任认定”，该节标题用“原因分析与教训”之类，不出现责任判定）。每套模板的章节 id、中英标题、每节需要的数据源。语言 lang ∈ zh | en | bilingual。GISIS Marine Casualties 上报字段定义（IMO 号、船名、船旗、船舶类型、总吨、事故日期 UTC、位置 lat/lon、事件类型、严重程度 Very serious/Serious/Less serious/Marine incident、死亡/失踪/受伤、污染、船舶灭失、调查国、报告状态等），每个字段带中英标签、必填性、取值来源（证据/案件字段编号）和校验规则；缺值为 null 且标“缺数据”。
2. 章节草稿：从已有结果取数（source adapters）：colreg 核查项（读 colreg 分析/核查项和复核状态，只读调用，不改 colreg 代码）、W14 推演对比表、W15 系统分析、询问比对（interviews crosscheck）、安全建议（recommendations）、证据（evidence）。W14/W15 目前 service 里没有数据——做成可插拔适配器，返回 missing，正文显示“缺数据：W14 推演对比表未提供 / Missing data: …”，**绝不编造**。每一句结论（sentence）都带 citations: [{kind: evidence|colreg-check|recommendation|interview-crosscheck|whatif|systemic, id, href}]，href 指向 web 已有页面（如 #/evidence?id=…、#/colreg?case=…&check=…、#/recs?id=…），引用的证据要过共享证据校验，未登记的引用标 unregistered 而不是丢掉。句子级中英文本 textZh/textEn（英文可用模板化句式，从同一结构化数据生成，不用 LLM）。
3. 人工确认：报告 report（每案可有多份，按 templateId+lang 创建）、章节 section、句子都有状态；新生成一律 Draft。对 section（以及可选 sentence）做 review：action ∈ confirm | dismiss | modify。dismiss/modify 必须有非空 reason（否则 422 report_review_reason_required）；modify 必须给新文本且与原值不同（否则 422 report_review_no_change）；confirm/dismiss 请求里夹带 text/textZh/textEn/新值字段 → 422 report_review_field_not_allowed（W6 裁定第 3 条同口径，不能静默忽略）。每次操作（生成、重新生成、确认、驳回、修改、导出、GISIS 校验导出）写审计（用已有 audit 服务和 audit-event 合同）：操作人（X-MCIS-Operator，沿用已有 context）、时间、原值、新值、reason 单独字段全文保存不截断（summary 可截断）。确认后保留 generatedText 和 reviewedBy/reviewedAt；修改后 source=Investigator 并保留原生成文本。提供审计查询端点。重新生成不得覆盖已人工确认/修改的章节——生成新版本（version+1），旧版本与复核记录保留。
4. 导出：PDF（reportlab，中文字体用项目 fonts/NotoSansSC-Regular.ttf）和 DOCX（python-docx，已装进 service/.venv）。lang 支持 zh/en/bilingual（中英对照）。每页/文档要有“DRAFT 草稿”水印或显著状态标注（未全部确认时），首页和页脚有“不作责任认定 / This report does not apportion blame or liability”声明，每章节标状态，引用以 [EV-xxx] 形式出现并附引用表，缺数据处显式标注。虚构案例的导出要标“虚构示例 / Fictional”。导出端点返回文件流（Content-Disposition、X-Sha256），并写审计。另有术语表（IMO 标准航海用语 SMCP 中英对照少量条目）可随附录导出或单独 JSON。
5. 虚构/真实：沿用 W6 做法。案件按种子标记分 fictional / real。只对虚构案例（CASE-2026-DEMO-LILY-MARY 等合成数据）提供完整功能。海力5 和 YANGZE 22（真实案例；caseId 从 haili5_seed.py 或已有标记读，YANGZE 22 若无则留常量占位）：GET 报告/模板端点返回 realDataStatus="pending-confirmation"，生成/导出返回 409 report_real_data_pending（消息：真实数据使用待 Mark 本人确认），不读 reports/、不读不复制真实报告内容，不调用 colreg evaluate，不写任何会覆盖海力5 种子的数据。web 页面有虚构/真实切换，选中真实案例显示“待确认”状态。
6. W6 页面“生成规则分析章节草稿”按钮的服务端接口：POST /api/v1/cases/{caseId}/reports/sections/colreg:draft（或你认为与上面统一的路径，在 REQUESTS.md 写清），生成一个 Draft 的“避碰规则分析”章节（引用核查项和证据，写审计），返回章节和报告链接。web 上做一个独立组件 web/src/reports/ColregDraftButton.tsx（props: caseId，调用接口、显示结果和跳转 #/report 的链接，真实案例显示待确认）。**不要改 ColregPage.tsx / ColregView.tsx**，接入那一步由外部完成。
7. web 报告页 ReportPage（#/report）：按原型第 15 页右两栏做——模板切换（IMO 格式 / MAIB / 中国海事）、语言切换（中文 / English / 中英双语）、章节状态条（概要/事实/分析/结论/已采取措施/安全建议/附录，显示 Draft/Confirmed/Modified/Dismissed/缺数据）、双语预览（句子带引用角标，可点回证据/核查项）、章节确认/驳回/修改（驳回和修改弹出理由必填）、审计列表、导出按钮（PDF 中文 / PDF English / PDF 中英对照 / DOCX / 术语表）、GISIS 字段面板（缺数据显式标注，JSON / CSV / 校验并导出）、虚构/真实切换、“示例数据（虚构）”徽标、“不作责任认定”声明。服务地址用 config.ts。风格与现有页面一致（复用 Panel 等组件）。
