## Source review
NewRoundInput trims nonempty draft/party fields and rejects duplicate case-sensitive party IDs; emitted payload always days30/isAgreedDeadline=false. Hash input is optional, formatted but not represented as a verified uploaded artifact. No custom/agreed deadline controls or external messaging.

Waiver wording explicitly records a previously confirmed decision and explains irreversibility; it does not decide for a party. Creation/waiver/closure use a separate confirmation step. Confirmation snapshot contains concrete body/path; case/role/operator remount and formEpoch changes discard old pending confirmations. Selecting another round also increments formEpoch. Read-only/unknown policy does not render lifecycle controls.

Closure hint uses allReplied or parsed exact deadline, never daysRemaining. Client time is labeled advisory; server remains authoritative and can reject premature close409. Closing does not require adopting every Pending comment and preserves later comment decisions.

All writes go through existing synchronous RequestGate. Mutation catch triggers onChanged(read-only parent audit reload) and a fresh policy/rounds read, never retrying POST/PATCH. Reload clears policy/rounds first; policy is restored only after both policy and rounds reads succeed. Failed policy/round reload therefore keeps writes blocked even if loading becomes false. A successful state reconciliation resets forms and reflects any already-committed operation. Parent audit retrieval is separate: its failure does not itself keep writes blocked when policy and business-round state have loaded successfully. This distinction is not hidden or claimed as transactional audit acknowledgement.

## Boundaries
Preexisting backend accepts some empty/whitespace/duplicate-party inputs not prevented by its schema and does not serialize cross-client open-round races. Frontend validation/request gate are not a backend concurrency/security fix. No source hash/seed rewrite or backend hardening was performed.

Actual browser interaction/lost-response injection and full service regression are coordinated separately and are not claimed by this source/static review. No screenshots uploaded, no real external outreach, no production data changed, no stage/push.
