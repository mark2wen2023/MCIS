## Known backend risks, not silently repaired
Current RoundIn party strings and draftVersion have no nonblank or duplicate-party validation, and schema does not enforce unique partyId. WaiveIn minimum length can still accept whitespace-only reasons; UI trimming is not an API security boundary. Open-round check plus n=len(rounds)+1 is not serialized by a surrounding cross-client lock: UI's single-instance request gate cannot guarantee concurrent clients never race. These are preexisting backend-contract/transaction limitations, not satisfied merely by frontend validation; do not present this UI slice as fixing them or alter service/schema without a separate authorization.

Current service close rule is all parties replied/waived OR deadline elapsed. Pending adoption decisions do not block closure and can still be decided afterward. Default UI offers no custom/agreed deadline. Expired-close rule is read from existing backend and should not be falsely claimed exercised by the future-deadline seed fixture; separate fixture manipulation would be needed for that boundary.
