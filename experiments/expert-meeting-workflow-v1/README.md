# Expert meeting workflow experiment (synthetic only)

Independent append-only slice for PR45. `node --test test.mjs` runs standard-library tests; `node demo.mjs` produces a read-only Chinese management snapshot `preview.html`. No server, install, browser automation, external network, production files or real evidence. The demo uses a small scripted fake panel, NOT Pi or an LLM. `panelFactory` can receive the `createPanel` export from the separate Pi integration experiment, but that wiring has NOT been executed or independently verified here. No claim of integrated MCIS functionality.

Workflow: human start → four independent whole-report reviews → human-confirmed agenda → investigator-selected issue and cross-examination → whole-report candidate suggestions. 海青君 is host identity metadata, not an implemented intelligent host. Final suggestions are supplied by the synthetic investigator harness, not generated by an LLM. No report-edit/adoption/archive operation exists. Experts have the four fixed roles only; case-specific additions/removals, avatars and personas remain design requirements requiring investigator confirmation.

MCIS wrapper owns a finite total count of provider operations (4–64), charges failed attempts, rejects concurrent operations and controls stage gates. This is NOT a token/cost/time budget or secure process sandbox. Per-agent loops/tool/model limits remain the separate adapter's responsibility. Pause prevents new work; an already running operation may finish and be retained while paused (drain semantics). Resume is rejected while busy. Cancel delegates cancellation and prevents late result publication. No durable state, real authentication, hard timeout or recovery after partial provider failure. `investigator` is fixture identity only.

Important integration gap: existing `createPanel.challenge(role,target)` accepts no focused-issue argument. Therefore selected issue currently labels the audit/turn only, NOT the model prompt or its semantic scope. Do not claim issue-specific model deliberation until the adapter owner adds and tests a host-controlled issue context. This experiment does not modify PR48 or the Pi integration. No source-security claims beyond the supplied panel factory; use synthetic material only.

The UI is an escaped HTML snapshot of before/during/after sections and remaining budget. It has no buttons and is not an interactive MCIS UI. Browser visual verification was not attempted due existing restrictions. Tests cover transitions, four-review gate, budget including failures, pause drain, cancellation, busy rejection, invalid agenda atomicity, copied views and HTML escaping. Independent review pending.

Independent-review fix: provider/panel output is untrusted. Recorded turn issue, speaker and target come exclusively from the coordinator's validated caller context; returned panel metadata is discarded rather than spread into the record. Only the candidate payload is retained as untrusted review material. This does not establish the candidate's truth, semantic relevance, speaker authorship or source support. A regression test injects forged issue/speaker/target fields and confirms they cannot overwrite the approved meeting context.

Early close is explicitly human-controlled: any agenda item with zero recorded challenges is listed as unaddressed, requires a nonempty reason to close, and is preserved in the view/audit and HTML summary. Even items with turns are NOT labelled resolved or fully discussed. Turn presence is only mechanical coverage, not substantive completion.
