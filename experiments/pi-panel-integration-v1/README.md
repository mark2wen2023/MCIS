# Four Pi expert integration experiment — synthetic only

This independent in-process experiment adapts the local PR48 adapter snapshot and exercises four actual `Agent` instances, one per role: regulation, navigation, investigation, vessel. 海青君 is host metadata, not a fifth expert. A trusted test harness acts as investigator and supplies a draft, provider functions and role source grants. All input/output is synthetic. It is not imported into MCIS, does not use PR45's SQLite persistence, and is not production code. No LLM, case data, network tools, shell tools or deployment are used. The injected provider is executable host code and is NOT sandboxed; no network-isolation claim is made.

The coordinator builds a separate Pi Agent, source copy, delivered-source set, call counters and provider function per role. It serializes operations, enforces independent reviews before mediated cross-examination, disallows self/unknown targets, limits turns, and binds a candidate to a source version delivered to that instance. It exposes only candidate outputs requiring human review. The host grants source IDs per role; a peer opinion is only shared where the receiver has every source grant held by its speaker; a turn additionally requires access to the target speaker's full grants. This is a conservative experiment, not complete information-flow security: the provider and opinion text are untrusted, actual provenance and semantic support are not checked, and references may omit sources. Production must implement authenticated case and per-operation authorization, redaction/classification, durable storage, snapshot digests, and safeguards independent of model/provider before any real material is used. `synthetic: true` and actor strings are NOT authentication or a classifier.

`npm test` runs two suites. The reported run used already-installed local Pi 1.5.2 dependencies, without installing packages or accessing the network. `npm ci --ignore-scripts` can prepare dependencies from the lockfile in an appropriate environment, but was not rerun here. It exercises four separate scripted providers, no peer text during blind review, peer visibility only after four candidate reviews, early/self challenge rejection, role-grant filtering for opinions and targets, turn exhaustion, cancellation, and a denied evidence source. The shared adapter's earlier test suite separately covers cross-case, missing/unread/version errors, malformed and unknown tools, batching, call budgets, cancellation before a tool body, and copied input. Those earlier checks do not automatically prove every property of this integration. Each expert's call budget spans all its runs; model-call limit, tool-call limit and panel turn limit are separate and are not token, cost, or wall-clock limits.

Known limits: no durable panel history, revision/idempotency/concurrency control across processes, or integration with PR45's Store; no genuine authenticated identity or secure process sandbox; only single-thread sequential orchestration, no security proof of per-role information flow or prompt-injection resistance; no human review/adoption UI, report edit/archive, model evaluation, real provider, token/cost budget, full cancellation under non-cooperative provider, or network isolation test. Peer restrictions are conservative, not a declassification policy. A failure after a provider call can leave an Agent context/call budget changed; that role is disabled for the lifetime of the panel rather than retried. The integration has no recovery or transactional retry. An added test covers two panels in parallel, serialization while a provider waits, and cancellation across a controlled provider await; it does not establish preemption of a non-cooperative provider or cross-process isolation. Do not merge or deploy on the strength of these tests.

Independent review reran both Node tests after the cancellation barrier and fail-closed change. It also tested a synthetic citation-laundering scenario separately. These checks support an experimental draft only. Cross-examination cancellation/failure, durable recovery, isolated provider closures, and real operating environment isolation remain unverified.
