# 统一船舶重建与坐标交接

在 Skill 目录执行下列命令。DWG 增加 --oda 和本机转换器路径。可用 --local-reference 提供具备源图指纹和未知横向位置说明的局部剖面 GLB，入口会按原图重新生成各件并逐节点核对顶点。读取 manifest.json 核对各项研究成果或受阻原因。

```sh
python scripts/s6.py drawings --out new-result
python -m unittest discover -s tests
```

| 数据 | 坐标与读法 |
|---|---|
| S2.1 geometry.json，S4.1 structures.json 和 evidence-graph.json | 沿用各字段声明的图面 WCS、局部板轴、船轴候选或相对肋位投影。原图和尺寸来源随记录保存。 |
| hull.glb | 船轴右手 X 向艏、Y 向左舷、Z 向上，或受限的对称局部船轴。顶点以米计，先减去精确原点，再转为 glTF 的 (x,z,−y)。asset.extras.coordinates 与清单同步。用逆旋转恢复后再加原点。 |
| 局部构件 GLB | X 表示沿肋号递增的偏距，垂直轴表示距基线高度，厚度以演示中面对称显示。frame_section_display 与 vessel 之间缺少的刚性安装变换保持未知。证据支持完整安装前，模型单独交付。 |
| 设备 GLB 与设备 JSON | 关节原点属于父坐标系，单位轴属于关节局部系。标准导出同时旋转局部顶点、共轭变换节点矩阵并转换关节参数。每个 GLB 含交换声明，每份关节 JSON 绑定 GLB 摘要。使用 s6_equipment.intake.read_articulation 读回。固定构件拥有独立节点。 |
| 旧剖面展示 GLB | 只接受与原图来源、逐节点几何及未知安装状态相符的参考，原样保存，禁止再执行船轴到 glTF 的旋转。 |

S5 的设备图入口识别显式 EQUIPMENT 注记，使用合成模板和约定轴。只有已明示共同原点的合成实验才使用 --synthetic-common-datum。实船遇到自然标注时须核对设备专图、轴线和安装位置，未知限制保留空值。S3 只支持上游已准入且附明确封盖证据的对称域。局部对称船体不能进入船轴设备装配。跨分项统计应注明目标及分母。

源版本为 S4.1 bedd9fd、S3 c9883e3（历史补丁独立提交 a247407）及 S6.3 b546eda。设备模块保留绘图解析、参数构件、关节控制、固定结构连接及标准导出，整合版本采用包内导入。S3 基准步骤见 benchmarks/s6/README.md。原始冻结包与完整离线回执可在授权本地环境复验。

## 分项状态及研究假设

默认 strict 模式。--mode demo 需要 --assumption 明确假设；原有 --synthetic-common-datum 表示合成试件采用共同基准。实体厚度仅由同图单位推得时，演示必须显式登记 same_sheet_thickness_unit_hypothesis。实船的局部显示中面不提供工程安装坐标。保留原样的历史 GLB 按模式命名，源文件指纹与原件属性随清单交付。

每次运行使用新目录。manifest.json 在每个分项开始及结束时原子更新。pending、running 表示尚未完成；exported、partial、blocked、failed 分别表示交付、有限交付、缺证或缺依赖、执行异常。reason、category 和 diagnostics 可定位缺项或错误。命令行在存在执行异常时退出 1，全部受阻时退出 4。其他分项的有效交付保留。输入身份改变会撤回本次运行的全部交付。

交付按各分项清单选取。structure/ 是 S4.1 原始中间证据，内含待审局部候选；diagnostics/ 保存运行失败时的现场。strict-quality.json 与 demo-quality.json 分别记录假设、质量、授权状态和已交付文件。两个模式都须另行获得工程授权；演示文件仅供研究展示。

处理甲板高度与横剖端点冲突时，在同一视图检查曲线末端有没有连续的直边、是否连接上下两条边界，以及折角线、甲板边线引线具体指向哪一段。保存单段与复合轮廓两次量测。侧视轴线、肋标刻线、中心线及设备中心的图元身份要分别核对；跨图尺寸相合不能代替三维安装证据。

## V1.0 研究候选的递归交付清单

入口先核对每份 DWG/DXF 及可选参考模型的指纹，再将校验过的临时快照供三个分项共用。每项结束及封存前会再次核对原件；观测到的改变会持续标记并撤回全部交付，即使随后恢复原字节。采样间变动又恢复无法从轮询证明，计算输入仍由副本指纹约束。

完成的 manifest.json 含 sealed=true 及 files。每条记录含相对路径、字节数、SHA-256、来源分项、运行模式及角色。清单自身是递归范围内唯一的例外，自身指纹应另存于验收回执。strict_delivery 表示严格研究模式准许交付，research_demo 表示带假设的演示资产。两者均无工程认证。intermediate_evidence 包括原始观测、质量报告和中间几何。diagnostic 包括日志、失败文件及已撤回产物。只按当前运行已登记的交付引用发放资产，扩展名不能决定交付角色。

通过下列命令完整遍历并复算，未封存、文件缺失、出现额外文件或角色与指纹不一致会报错。清单是完整性记录，认证其发布者仍需可信的外部指纹。

```sh
python scripts/s6.py --verify --out previous-run
python scripts/s6.py drawings --recover-from previous-run --out recovered-run
```

恢复采用新目录完整重跑，绑定旧清单 SHA-256、具名输入图纸、参考模型、模式及假设。恢复演示时重复给出原演示选项。中断的运行只要留有初始清单即可作为恢复来源。恢复不复用未封存资产，不覆盖旧日志。
