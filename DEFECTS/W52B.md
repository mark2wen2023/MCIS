# W5.2b independent defect record

## D1: SQLite writer / Python audit-lock inversion (synthetic reproduction)

Independent deterministic interleaving used actual manual POST and package export requests: manual acquired BEGIN IMMEDIATE and paused before audit; export held WRITE_LOCK and waited for BEGIN; resuming manual made it wait for WRITE_LOCK. After approximately5.11s SQLite timeout, export returned500/no-store while manual returned201. No original-text loss or disclosure was observed. This was a bounded lock-order/recoverability failure, not an infinite deadlock. Initial40 API/DB and real-browser tests did not cover this interleaving; their pass must not be represented as final acceptance.

## Correction under independent review

Only successful explicit BEGIN IMMEDIATE may bind a writer reservation to the exact current SQLAlchemy root transaction, connection and thread object. audit.append may omit the Python lock only when that same active physical SQLite writer is proved; SQLite serializes audit sequence allocation until commit. Ordinary reads, unproved transactions, stale/rolled-back/reused contexts and non-SQLite retain existing behavior. Proven outer reservations persist through savepoints; unproved legacy nested transactions are not certified by this change. No authentication or all-route/multiworker safety claim.

Required retest: manual and legacy transcript mutation versus export; both legal serialization orders and no mixed snapshot; rollback/commit/savepoint lifecycle, connection/thread reuse, fallback paths, actual independent-process reserved-writer sequence/hash chain, all scoped regression and real browser. Final disposition pending independent re-verification and refreshed freeze.

## Independent final disposition

D1 resolved within the tested W5.2b scope after final refreeze.
