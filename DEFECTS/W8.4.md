# W8.4 独立验收

## D01：案件包缺省字段规范化与跨包版本边界

首轮独立后端 39 通过、1 失败。新建案件未提供 accidentCode 等可选字段，导出/重新导入时既有 case.json 序列化补入空字符串，导致完整 case/revision 与导出前不逐字相等。不能把首轮结果称为全通过。

主实现裁定：不修改原 package 序列化，不扩包。运行时 null 清除是移除键；跨包沿用原格式的“未填写”规范化，leadInvestigator/agencyName/summaryNotes 缺键可转为空字符串，placeName 位于扩展文件中仍可缺失。空字符串不构成补造事故事实。非空文字和完整审计必须原文保留。revision 是当前库快照的并发标识，不承诺跨包恒等；规范化改变快照时旧 token 必须拒绝。

保留首轮失败记录和原测试目的，按裁定改写为逐字段原文/未填写语义、既有只读值保持、完整审计 reason 保持、revision 改变与旧 token 拒绝，并追加三个清空字段的包往返用例。合同 v2 冻结复验：43 个独立后端用例及 4 个合同用例通过。产品服务未因本裁定改写。

## D02：旧空白名称导致整个编辑页拒读

独立真实浏览器复现：既有 POST /cases 对 title 三个空格返回 201，GET metadata 返回 200 并原样保留，W8.4 页面只显示无法读取且无编辑按钮；直接 PATCH 合法名称返回 200。最小用例 legacy_blank_browser.cjs，首轮失败保留于本地未发布历史产物 legacy-blank-v1-results.txt（不随仓库发布）。此为读侧错误套用写侧验证造成的实际修复入口阻断，已交实现方；修复后 UI v2 冻结已独立复验：空白与空字符串旧名称可读并显示未填写，原值可编辑；新空白写入仍被拒绝，合法修改可经真实 UI 保存及重开。正常浏览器扩展至 39 项通过，冻结前后哈希一致，D02 关闭。
